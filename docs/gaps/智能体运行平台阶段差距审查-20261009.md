# 智能体运行平台阶段差距审查（2026-10-09）

## 先说重点

**结论：已有专用运行概览和实例内 MCP 管理，但分属两个实验；还没有一个把两者接通并通过业务验收的运行平台。** [EXP-013 概览 Candidate](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/observations.md)采集 DSH 会话和委派事件；纯编号的 [EXP-013 MCP Candidate](../../evolution/experiments/EXP-security-operations-expert-013/evaluation/observations.md)提供实例内 MCP 管理。下文分别简称“概览 Candidate”和“MCP Candidate”。

- **P0 先做：**确定首个使用场景，把概览和 MCP 管理接到同一试点来源；复核并解决巡检服务三项与资产四项工具的不一致，让平台看到真实的 Agent 与实例状态，并用业务任务验收。
- **P1 接着做：**从业务对话追到原始执行记录，贯通来源编辑与回退、实例生命周期；管理对话和恢复能力随实际写操作接入。
- **P2/P3 按需做：**资产 Hub、反馈评估、研究版本、多用户、业务发布和低算力部署均有明确触发条件，不作为首个试点的统一门槛。

这里的“差距”是相对于**拟启动的运行平台**而言，不把未来功能倒算为现行 Research Mode 的缺陷。优先级中，P0 是确定首个试点并使它真实可用的事项；P1 是首个用户闭环需要的支撑能力；P2、P3 要由实际复用、长期服务或多人使用触发。

## 当前已经做到哪里

**运行概览已有真实数据链。** 概览 Candidate 以 EXP-011 完整界面为起点，融入 EXP-012 四工具合同。插件从 DSH 会话列表和委派事件生成当前实例的四张卡片；一次真实故障分析委派在重启后仍显示主会话 1、故障分析完成 1，并能打开子会话。其余两种子智能体和失败路径只有插件测试证据。[浏览器原始记录](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/evidence/overview-browser-after-20261009.json)、[实验观察](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/observations.md)。

卡片上的“工具调用”是近 24 小时 DSH 工具结果事件的次数，“Skill 加载”是成功加载或显式调用事件的次数，**不是可用工具总数或已配置 Skill 数量**。采集启用前不回补；实际浏览器验收只见过四张卡片的零值，非零计数尚未做真实端到端核对。实例停止后，该实例内的概览 API 也无法独立报告容器已停止，不能把页面上的“空闲”理解成宿主层“健康”。[计数观察](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/observations.md)、[统计实现](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/candidate/dsh/managed/security-operations-ui/index.js)。

**MCP 管理也有实例内实绩。** MCP Candidate 提供服务器、分组、连接检查与 OpenAPI 来源页面。浏览器保存过 Web profile，受控 MCP 服务完成握手、工具发现、分组限制和调用；真实 OpenAPI 规范发现 121 个操作，但目标业务接口在未提供 API Key 时返回 401，没有完成目标业务调用或业务 Run。MCP Candidate 有管理插件；概览 Candidate 中未找到该插件。因此，两个实验的成功项不能相加为一个已验收实例。[MCP 实验观察](../../evolution/experiments/EXP-security-operations-expert-013/evaluation/observations.md)、[MCP 插件源码](../../evolution/experiments/EXP-security-operations-expert-013/candidate/dsh/managed/mcp-manager/index.ts)。

**现有 CLI 可复用。** research-tool 提供来源、编辑、运行、比较和实例命令，其实例查询还能检查镜像及只读挂载；dsh-dev 能启动、查询和重建评测实例。EXP-012 的所选三项巡检 Case 在当时的服务条件下两次通过；资料定位的命令数从 4 降到 1。它们还没有证明长期实例管理、稳定省时或平台业务验收。[研究入口](../../runtime/adapters/dsh-container/research-tool.mts)、[EXP-012 观察](../../evolution/experiments/EXP-security-operations-expert-012/evaluation/observations.md)。

## P0：先补首个试点的硬缺口

### 1. 定义平台第一条用户路径

平台方案以长期业务 Agent、独立用户或统一业务调用作为按需启动的条件；本仓库的现行项目规则仍只定义 Research Mode。应先选定具体使用者、Agent、实例、允许的读写操作、预期运行时间与验收任务，再决定在本仓库明确开启新阶段，还是在独立工程承接。首个验收对象可以是一条“选择 Agent 和实例 → 查看实际装载与状态 → 完成两轮业务对话 → 找到原始执行证据”的路径。没有这个决定，页面越多，越难判断什么叫完成。[平台方案](../platform-design/README.md)、[项目解释](../standards/PROJECT-INTERPRETATION.md)。

### 2. 让同一个试点来源具备所需能力，并解决巡检合同失配

概览 Candidate 的专用概览与 MCP Candidate 的管理页分属两个实验。首版若同时需要两者，应在明确选定的 Experiment 来源中合入必要插件和配置，以新实例核对实际装载；保留各实验既有 Run 的原始结论，不把“代码可见”当成“同一实例已生效”。[概览 Candidate](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/hypothesis.md)、[MCP Candidate](../../evolution/experiments/EXP-security-operations-expert-013/hypothesis.md)。

巡检是本次证据中更直接的阻塞：2026-10-09 留存的 tools/list 只返回 list_executable_inspections、start_inspection、get_inspection_result，与 Candidate 期待的四工具不一致；U-INS-002 因未查询到目标目录而失败，还发生一次最终失败的策略 Operation。后续 Guard 修正只有插件单元测试，没有新实例和新 Session 的业务 Run。应先复查现用服务目录，取得匹配的真实服务或调整被测合同，再核对工具发现、Guard 装载和所选 Case；不能沿用 EXP-012 在旧环境中的成功判定。[服务目录原始记录](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/evidence/inspection-tools-list-20261009.json)、[本次实验观察](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/observations.md)。

### 3. 建立平台可核对的 Agent 与实例状态

现有概览回答的是“当前 DSH 实例内这些会话和委派最近怎样”，没有跨实例列表，也没有把 Agent ID、实例 ID、期望来源、容器状态和实际装载快照连在一起。research-tool 的实例查询能检查选定来源的镜像和挂载，但它是 CLI，不是平台状态页。[概览实现](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/candidate/dsh/managed/security-operations-ui/index.js)、[实例查询](../../runtime/adapters/dsh-container/research-tool.mts)。

首版状态页应分别显示容器是否运行、DSH 会话是否活动、实际装载的镜像与 Harness 来源、最近观察时间和错误。失联或数据过期时显示“未知”，不能继续沿用上次“正常”；单个 Agent 的主、子智能体活动可以复用现有事件数据，页面则按平台选定的 Agent 与实例重新组织。完成时用真实实例的启动、停止、重启与失联观察页面变化，并核对一次非零工具调用和 Skill 加载的角色归属。

### 4. 把实例内 MCP 管理接到真实业务与平台身份

MCP Candidate 的三页管理界面已经能修改单实例 Web profile、检查受控连接并通过分组端点调用工具；它还不是按 Agent/实例查看和管理的通用页面。首版应使页面明确当前实例、配置来源、已声明与已发现工具、最近核验时间及连接错误。修改后需要在新 Session 看到实际工具目录与一次目标业务调用；目标业务接口的认证条件要真实满足，再评价业务结果。Web profile 在线工作态与 Candidate 种子各有用途，不能维护另一套重叠的可编辑 MCP 清单。[MCP 实验观察](../../evolution/experiments/EXP-security-operations-expert-013/evaluation/observations.md)、[平台方案](../platform-design/README.md)。

## P1：首个用户闭环需要接通的路径

- **业务对话和 Trace。** EXP-011 与两个 EXP-013 留下推荐任务、数字员工卡、模型回复和局部浏览器证据；概览 Candidate 还证明一次故障分析委派完成。仍需在选定实例内实际完成多轮业务会话，从回答定位同一 Session 的消息、工具事件、子会话、错误与最终结果，并核对断线或取消后的归属。语音及其他子智能体只在首版向用户开放时补验。[EXP-011 观察](../../evolution/experiments/EXP-security-operations-expert-011/evaluation/observations.md)、[概览实验观察](../../evolution/experiments/EXP-security-operations-expert-013-r26ecd1295ab4/evaluation/observations.md)。
- **来源、编辑和回退。** research-tool 已能选择 Experiment、编辑 Candidate、显示 Git 差异及查看实例；还缺“平台选择精确来源 → 修改 → 新装载 → 行为核对 → 切回旧来源”的一条连续实测路径。每次应区分 Git 提交与 dirty 状态、期望配置和实际加载；实例同名不能证明资产相同。[研究入口](../../runtime/adapters/dsh-container/research-tool.mts)、[PA-07](../ai-agent-harness项目验收矩阵.md#pa-07-宿主修改装载观察与回退闭环)。
- **长期实例和操作结果。** dsh-dev 目前的创建模式是 eval/verification，服务研究试验；长期业务实例的期望状态、启动/停止/重建结果、活跃会话影响和平台重启后的对账尚未实现。若首版只读观察，可先不接管容器；若提供写操作，就要把实例目标、操作回执与实际结果连起来，分别处理容器与会话数据。[启动器](../../runtime/adapters/dsh-container/dsh-dev)、[平台方案](../platform-design/README.md)。
- **管理对话。** 仓库有研究 CLI 和业务 DSH Web，尚无让平台页面与管理智能体共用的确定性实例操作服务。只有首版确实要用自然语言管理时，才需提供目标预览、明确执行结果和可重查的操作记录；模型叙述不能充当操作成功回执。[研究入口](../../runtime/adapters/dsh-container/research-tool.mts)、[平台方案](../platform-design/README.md)。
- **状态保存与恢复。** Candidate、Web profile、容器、DSH Session、Run 和未来 Trace 索引是不同事实。平台一旦持有长期实例或配置写入，就要明确保存、恢复及删除影响，用一次重启或受控恢复验证仍能定位会话和原始证据；不把整个 DSH HOME 复制为 Harness 资产。[项目解释](../standards/PROJECT-INTERPRETATION.md)、[平台方案](../platform-design/README.md)。
- **逐功能验收与研究判断。** 当前 PA-01—11 只描述研究项目与工具链，不能代替平台验收。EXP-012 的 Decision 仍是 AI 临时 continue，工具定位命令数虽减少，稳定工时或错误率收益尚未证实；这些研究判断应由人核对原始证据。平台每开放一项功能，也要从浏览器追到服务、DSH/容器事实与用户可见结果，记录失败和未知。[验收矩阵](../ai-agent-harness项目验收矩阵.md)、[EXP-012 Decision](../../evolution/experiments/EXP-security-operations-expert-012/decision.md)。

## P2：第一条路径有效后，按复用需求建设

- **Harness 资产工作台与能力 Hub。** Agent 创建、Candidate 页面编辑，以及 Skill、Plugin、知识目录的导入、绑定、升级和移除尚无平台路径。已有实例概览的 Skill 加载次数只是活动计数，不等于 Skill Hub。真实跨 Agent 复用出现后，再复用现有来源与只读装载机制逐类接入，不复制第二份资产。[平台方案](../platform-design/README.md)。
- **反馈、测试和评估界面。** 现有 evaluation.md、Run、Decision 是事实源；业务反馈收集、从失败 Trace 提案 Case、页面选择口径、人工复核与逐例对照仍是设计方向。只有非 CLI 使用者或真实反馈形成后再连接。[项目解释](../standards/PROJECT-INTERPRETATION.md)、[平台方案](../platform-design/README.md)。
- **可复现版本、工具组合和算力 Variant。** Research Release 的打包与复现仍未实现，不能把 Candidate 或研究 Decision 叫作已发布业务版本。OpenAPI 工具组合和低算力派生也未证明业务等效与资源收益；EXP-010 的相关研究仍为 inconclusive。它们不应阻塞首个单实例观察与对话试点。[PA-11](../ai-agent-harness项目验收矩阵.md#pa-11-research-release-打包解析与复现装载)、[EXP-010 Decision](../../evolution/experiments/EXP-security-operations-expert-010/decision.md)。

## P3：真实长期业务场景出现后再启动

多 Agent 统一对外入口、不可变业务版本与新 Session 切换、多人共享同一 Agent 的会话和任务归属、容器与凭据的长期运维、低算力客户部署和自动扩容，目前没有与之对应的使用者和完整实测。这些工作分别由多 Agent 对外服务、实际版本替换、第二位用户、容器写操作或资源瓶颈触发。若首版已经开放容器或凭据写操作，相应的最小身份、执行和恢复边界应随该操作前移；不必因此预建一整套多用户平台。[平台方案](../platform-design/README.md)、[项目规则](../../AGENTS.md)。

## 与上一版审查相比，以及本次证据边界

上一版把“真实运行状态”和“MCP 页面”写为仓库中未见实现，**这两句已不准确**：前者已有单实例专用概览，后者已有 MCP Candidate 的单实例管理页。新的差距是两项能力尚未在一个已验证的业务来源中汇合，且都未覆盖跨实例的平台职责。上一版对 EXP-011 故障分析超时的描述也不能代表最新状态：概览 Candidate 已有一次真实委派完成，但回答质量和其他子智能体仍未验证。历史 1—38 项的其余研究、低算力、发布和多用户议题按上面的 P1—P3 触发条件处理，不将旧清单逐行复制为第二份需求源。
