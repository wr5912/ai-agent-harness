## 范围与结论

仓库当前仍处于 Research Mode。长期方向是“研究验证 → 自用工具 → 能力逐步完善 → AI 原生的 Harness 工程平台”；阶段转换时复用已验证的资产、来源和 Run，不预设新仓库或生产平台。[项目规则](../../AGENTS.md)、[平台方案](../platform-design/README.md)。本文件记录走向其中**运行管理能力**的证据与差距，不把未来平台功能列为当前研究仓库的缺陷；项目与工具链的 `PA-xx` 状态以[验收矩阵](../ai-agent-harness项目验收矩阵.md)为准。

**当前判断：巡检与问答的重复研究闭环、首条 API 路径及双实例身份和状态核对已留下新证据。结构化输出在所选重复中改善，自动评审仍有分歧，巡检仍为 `PARTIAL`，人工查证效率收益尚未证实。跨实例页面和指定试点地址仍需另行验收。** 历史概览→MCP 配置→巡检与续查已在 EXP-015、EXP-017 的不同实例各走通一次；两个新 HOME 的正式浏览器 Run 另通过简单 UI 冒烟，EXP-017 周期任务已有两次真实到期。这些历史证据保留原边界。 `server/discover` 返回 HTTP 200、JSON-RPC `-32601 Method not found` 不阻塞已观察到的 DSH 使用：保留服务签发的 Session，依次执行 `initialize → notifications/initialized → tools/list` 后能发现并调用巡检三工具。单独的 HTTP 状态码不能证明工具可用。[协议观察](../../evolution/experiments/EXP-security-operations-expert-014-r8b1bd54e8be7/evaluation/observations.md)。周期巡检使用 DSH 自动化任务插件；[EXP-017](../../evolution/experiments/EXP-security-operations-expert-017-r94f3b07e080f/evaluation/observations.md)已取得任务创建、两次到期投递及对应三工具调用的原始回执。

**平台最初阶段的完成标志：** 已有只读平台通过本分支实机验收，并能沿一项真实任务追溯 Agent、Experiment、Run、冻结输入和原始证据；研究者试用后能够说明查证耗时、遗漏或来源判断的变化。之后才按实际需要连接现有 Case 执行、生成新 Run 和比较结果，再考虑 Candidate 编辑。平台继续属于 Research Mode，`PA-12`、Experiment Evaluation 和业务验收分别记录；Research Release、多用户和完整运行管理按真实需求触发。

## 当前 Research Mode 先补的闭环

## 运行平台阶段的 P0：选定试点后逐项验收

1. **首条 API 路径已有局部证据。** 本轮在隔离本地实例核对来源、镜像、只读装载和 Session 身份，调用真实巡检三工具，并在同 Session 只按原 `runId` 续查；回答与本轮原始回执对齐。`PARTIAL / ABNORMAL` 保留部分完成和证据缺口，不判完整业务通过。当前等待时间未知，执行器的超时仅限制测量；历史浏览器首轮超过 120 秒后才完成的失败记录保留。目标地址和页面的服务承诺在实际选定时另验，不阻塞当前 API 研究。[本轮观察](../../evolution/experiments/EXP-security-operations-expert-018-rfbf7fd53a340/evaluation/observations.md)。
2. **双实例对应关系已有 API 与容器证据。** [最终十条观察](../../evolution/experiments/EXP-security-operations-expert-018-rfbf7fd53a340/evaluation/evidence/instance-observation-final-20261013.json)逐条关联 Agent、实例、来源、实际镜像、三个只读挂载、已装载指令摘要、Session、容器状态、DSH 活动和 UTC 观察时间。活动由实际 `turn/start` 与 `turn/end` 判定；A 停止时记录容器退出、API 不可达和 DSH 状态未知，B 保持空闲，A 重启后原 Session 恢复。这些结果未验证跨实例页面，也不能把历史空闲状态当作当前容器健康。

## 按实际使用触发的后续能力

- **来源修改与回退。** 研究 CLI 有来源、差异和实例操作；平台写入出现时，需实测“改 Candidate → 新装载 → 行为核对 → 切回旧来源”，并区分期望配置与实际加载。现有 [PA-07](../ai-agent-harness项目验收矩阵.md#pa-07-宿主修改装载观察与回退闭环)只部分覆盖。
- **长期实例、Trace 与恢复。** 仅当试点提供持续服务或容器写操作时，连接启动、停止、重建、活跃会话影响、操作回执与重启后的状态对账；保存 Session 与原始证据在运行存储，不把 HOME 复制成 Harness 资产。[平台方案](../platform-design/README.md)。
- **能力 Hub、反馈评估、版本与多用户。** 跨 Agent 复用、非 CLI 使用者、独立研究版本或第二位用户出现后再逐项建设。Research Release 的[复现路径](../ai-agent-harness项目验收矩阵.md#pa-11-research-release-打包解析与复现装载)尚未实现，不是首个单实例试点门槛；多人共享时需另验 Session 与任务归属。[平台方案](../platform-design/README.md)。
