## P0：阶段决定与已指定页面

### P0-01 确定首个使用场景和新阶段合同

当前[项目规则](../../AGENTS.md)只授权 Research Mode 内的 CLI 研究，[平台方案](../DSH智能体运行管理平台设计方案.md)把运行平台的启动条件写为长期业务 Agent、独立用户或统一业务调用等实际需求。页面任务清单给出了 G1a/G1b/G2/G3 的设想，但“谁先用、管理哪个 Agent、要保持多久、哪些操作可写、什么行为算可用”尚未变成当前项目合同。若不先划定首版边界，`HarnessVersion`、多用户、Hub、业务部署容易被一起预建，同时现有验收矩阵也无法给新用户路径下结论。

**完成证据：**明确首个真实使用者、Agent、管理和业务任务、允许的实例操作、运行时间与验收方式；决定继续在本仓库明确切换阶段，还是另建平台工程。用一条“管理任务 → 真实实例 → 两轮业务对话 → 原始执行证据”的路径作为首版验收对象；当前 Research Mode 的资料与 Run 保持原事实源。阶段合同确定后再更新适用规则和平台验收口径。[平台方案](../DSH智能体运行管理平台设计方案.md)、[项目解释](../standards/PROJECT-INTERPRETATION.md)。

### P0-02 完成已指定的“智能对话”界面范围

旧清单第 36 项已有部分实绩：EXP-011 的推荐、数字员工、收藏、搜索、草稿插入、一个模型回复和威胁研判浏览器 Run 有对应观察，不能继续写成“尚未开始”。同一记录又显示故障分析父 Session 两次超时、其他推荐卡的外部 MCP 业务结果未覆盖、远程语音在撤去临时 HTTPS 入口后未重测；其 Decision 仍为 `continue`。界面复刻本身也不创建真实子智能体，浏览器本地卡片不应进入平台 Agent 数量。[观察](../../evolution/experiments/EXP-security-operations-expert-011/evaluation/observations.md)、[Decision](../../evolution/experiments/EXP-security-operations-expert-011/decision.md)、[页面源码](../../evolution/experiments/EXP-security-operations-expert-011/candidate/dsh/managed/security-operations-ui/client.tsx)。

**完成证据：**按已约定的可用卡片逐项在当前入口新建 Session、发送、查看工具与最终答复；故障分析若仍是交付范围，先查父 Session 完成条件并形成新浏览器 Run；语音若仍对外提供，再对实际入口补验。只宣称已验收的交互，不把单次 HTTP `200`、截图或本地卡片编辑写成业务能力通过。

### P0-03 建立真实的“智能体运行状态”页面

旧清单第 37 项要求按 Agent/实例显示状态、实际装载版本、观察时间和错误。当前 `research-tool instance` 能查询所选来源的既有实例并核对镜像与只读挂载；EXP-011 的“运行概览”只由本 DSH Web 的 Session 状态推算，没有跨实例容器、镜像、目标与实际快照的数据链。仓库中未见该平台页面与服务实现。[研究入口](../../runtime/adapters/dsh-container/research-tool.mts)、[页面源码](../../evolution/experiments/EXP-security-operations-expert-011/candidate/dsh/managed/security-operations-ui/client.tsx)、[EXP-012 实例原件](../../evolution/experiments/EXP-security-operations-expert-012/evaluation/evidence/research-tool-instance-20261008.json)。

**完成证据：**页面以精确 Agent ID 与实例 ID 对齐期望来源、容器观测和最近采样时间，区分运行、停止、失败、未知和数据过期；显示镜像、Preset、挂载摘要及错误来源。用一个真实实例启动、停止、重启、失联，再在浏览器核对各状态变化；状态无法读取时显示未知，而不沿用上次“正常”。

### P0-04 建立最小 MCP 管理页面

旧清单第 38 项要求能看服务、工具、归属、连接和配置生效。EXP-012 已证明特定 Candidate 的四工具 MCP 可以装载和调用，正好能作为首个真服务；但当前配置文件、CLI 和 Run 不提供跨 Agent 的登记、变更预览、连接诊断或页面。若页面只读静态 YAML，就会把“已声明”误称“可调用”。[EXP-012 观察](../../evolution/experiments/EXP-security-operations-expert-012/evaluation/observations.md)、[Candidate MCP 配置](../../evolution/experiments/EXP-security-operations-expert-012/candidate/dsh/managed/mcp-servers.yaml)、[平台方案](../DSH智能体运行管理平台设计方案.md)。

**完成证据：**首版围绕一个真实 MCP 显示服务及工具、配置来源、凭据引用是否可用、握手/发现结果、实际调用和最近核验时间；新增、修改、停用写回目标 Candidate 的唯一配置源，预览差异，使用新实例或新 Session 验证装载和调用，连接失败展示原因。不得在页面、普通日志或报告中暴露凭据值。组合工具画布和通用市场留待确有复用需求后建设。

## 验证边界与下一步

本次进行了仓库源码、文档、已封存 Run 与观察的核读及页面/平台入口检索；**没有重新启动 Docker、访问现运行实例、连接外部 MCP、执行新 Run、在浏览器重测页面或做双用户/客户现场试验**。因此，历史实机记录只证明记录当时的来源与观察，当前在线状态、平台外部实现及耗时收益仍未知。静态未找到页面只支持“当前仓库无可核对的实现”，不支持“任何环境都不存在”。
