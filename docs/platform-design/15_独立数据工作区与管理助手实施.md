## 发现与整改

- 原生 MCP Patch 以插件 ID 和 `name` 一起匹配。HOME 迁移后原文件 URL 导致完整连接配置被静默忽略。prepare 现在只重定位本平台已知 MCP 插件的 URL，启动检查能识别未迁移状态。连接、分组、Token 及其余 Patch 字段迁移前后相等；原 3 个连接、2 个分组恢复生效。
- 原生模型设置保存会将长 `name` 写成合法的 YAML 多行字符串，原单行解析因此阻断下一次 prepare。已使用 YAML 节点及源码位置解析，当前正确引用原文保持不变，迁移只替换目标标量；24 项启动器回归覆盖原生折行、旧引用迁移、换行保留及缺依赖提示。
- 标准镜像指纹曾包含未进入镜像的来源解析脚本。已改为实际镜像输入，重新构建的唯一标准镜像具有与原镜像完全相同的 12 个文件系统层。两个正式实例共用该镜像，不因业务 Harness 变化生成派生镜像。
- 平台 API、CLI 和目录监听对 `~`、相对实例状态路径的解释不同。已统一为同一数据根和 HOME 解析规则，明确环境变量覆盖优先级。
- 共享实例状态目录曾允许读取并操作另一工作区的登记。平台与 CLI 现共同核对工作区身份、资产根与明确迁移来源，并核对实际容器的 Compose 路径。新建时拒绝全局同名冲突，旧工作区也不能操作被另一工作区复用的同名容器。Python 描述符校验与 TypeScript 同步。117 项生命周期 Python、7 项路径 Python、15 项 TypeScript 定向回归及真实实例列表读取通过；冲突分支使用真实控制流和模拟 Docker 查询，没有创建实际冲突容器。
- 成功 Run 保存实际轨迹时未填写轨迹可用标志，导致消费者误报缺失。现在按保存结果记录，非空只表示可用，完整性仍由原始轨迹、步骤配对和封存校验分别判断。
- 算力变体确认后的 Candidate 或计划发生变化时，旧 end 标记不能继续排除主线融合；融合盘点重新核对固定版本和当前内容。
- 管理助手的混合任务曾出现 MCP dry 参数错误和转为实际调用提案的倾向。实际执行被确认机制阻断，提案已取消；Skill 已补齐跨业务切换、真实参数及 dry 失败后的处理。独立 MCP 任务已成功 dry 验证，但资源发现的错误推断仍作为模型效果限制保留。
- 算力计划生成曾对原生工具冻结的参数数组原地排序，真实 AI 调用失败而普通 RPC 测试通过。已复制数组再排序并覆盖冻结参数回归。首轮模型随后进行了 63 次 shell 诊断，虽未改变业务资产，仍超出策划范围；专用会话现只提供专用 Skill 与平台工具，限制取证规模并明确内部错误停止条件。
- 初始化引导保留既有配置并补齐必要文件与忽略规则，失败可重试；从 Git 克隆后先展示实际扩展内容，再确认构建。初始化后的跳转读取实际站点前缀，避免合法自定义路径初始化成功却无法进入平台。
- 四个管理页移除与导航重复的 H1，保留无障碍名称和操作入口。算力变体收敛为 AI 主入口、手动计划次入口、右侧刷新；两种方式共用预览与确认流程。修复初次读取与刷新的竞态，以及长版本名称使窄屏下拉框被裁切的问题。MCP 保存操作与标签栏同排靠右，窄屏可换行。
