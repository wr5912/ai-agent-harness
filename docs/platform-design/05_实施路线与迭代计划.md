# 05｜实施路线与迭代计划

本章是 R0–R5 定义、依赖和进入/退出条件的唯一维护位置。阶段描述可复用能力的演进，不是按日期自动推进的项目状态；其他章节只引用本章。原任务 G 分级、当前 PA 验收路径和这些阶段各有含义，不能互换。

## 1. 按真实故事选择路径

```mermaid
flowchart LR
 R0["R0 研究证据可信"] --> R1["R1 重复操作工具化"]
 R1 --> R3["R3 受控改进闭环"]
 R1 --> R2["R2 数据身份与恢复"]
 R2 --> R3
 R3 -.第二消费者或业务需求.-> R4["R4 服务与按需交互"]
 R4 -.独立需求.-> R5["R5 逐项产品扩展"]
```

变体、数据库、Meta、MCP 组合和多人业务是条件分支。未选择的能力不成为阶段门槛；选择后必须满足该故事的真实前置依赖。允许长期停留研究或自用工具阶段。

## 2. 阶段定义、交付与条件

### R0｜可复核的 Harness 研究

选一项有价值的实际输入、失败或新目标，固定 Baseline、Case、口径、来源、镜像和模型/工具。按 [03 的比较环境合同](03_存储架构与数据契约.md#comparison-environment)核验外部状态，再运行真实 DSH 并保存 Run、回归、限制与人工 Decision。

首个 Experiment 可使用 `none:first-experiment`；缺少有效 Baseline、状态不可控或证据不足时，不虚构对照成立，记录 `continue/inconclusive` 及缺口。只有研究假设涉及资源或组件变化时才选择变体探针；Research Release 重载只有实际需要时才补齐。

**交付与 G-R0**：能从固定输入、来源和记录复核结论，重跑对照或解释不能复现的原因；Case/Candidate 没有第二可编辑来源。该门槛不要求失败 Case、第二配置、变体、固定 Case 数或 Research Release。研究未获得证据时继续研究，不能以文件存在通过。

<a id="self-tool-value"></a>
### R1｜把重复研究动作做成自用工具

选择一个已有 Agent 和一项真实问题，连接来源定位、完整 Case/Run 查看、差异、评测、比较与 Decision；也可只选一个高频实例查询故事。先复用现有 CLI/Skill，确定性入口不依赖 Meta。保持 JSON stdout、诊断 stderr、退出码、超时/取消及 dry-run 的实际语义。

界面或命令读取原 `evaluation.md`、Run 和 `decision.md`，不另建 Case 库或建议库。显示失败、反驳观察、未覆盖输入及实际装载。第二个 Agent 或 Variant 仅在验证复用价值时选取，不是首个工具门槛。

**交付与 G-R1**：选中的操作实际反复使用，前后步骤、来源错误、耗时或遗漏可核实改善；无收益就简化或停止。阈值由真实基线与研究目标确定，不由路线图虚构。

### R2｜数据身份、写权与恢复

按 `03` 定义实际使用对象的 ID 作用域、写者、生命周期、固定来源和恢复路径，从真实 Run 定位正确 Instance/Runtime/Session；试验中途退出、重启、状态未知和索引重建。没有真实对象时不预建表。

Git/文件足够就继续使用；查询或并发事务确有问题才比较 SQLite/PG 成本与恢复收益。Trace A/B 决策单独遵循 `03`，普通引用可恢复不能证明 TR02 的平台持久 ACK。

**交付与 G-R2**：选定对象关系与恢复经过实际验证，引用不串实例，同一事实只有一个可编辑入口。数据库是可选实现，全部候选表与持久事件采集均非通用门槛。

### R3｜工具级受控改进闭环

从真实 Run/Session 问题产生带来源的 CaseProposal，人工确认后改唯一 Case，复用研究技能建立 Experiment/Candidate，按 `03` 执行比较并写 Decision。统一入口连接这些证据，不改变其写权。

**交付与 G-R3**：选定问题完成可复验的提案、改进、比较和人工判断，未知副作用不盲重试，没有第二 Case/Candidate 源，并验证重复使用收益。仍需手动的步骤如实记录；不要求先建 Service、Web 或 Meta。

### R4｜确定性服务与按需交互

**进入条件**：已有工具被重复使用，出现第二消费者、非 CLI 使用者或真实长期业务会话，并能指出预期节省的步骤。图片和完整任务库存不构成开工依据。

- **R4a：共用 Service/API**。仅提取被第二消费者需要的能力，CLI 和新增入口同源；按实际动作提供预览、确认、回执与对账。
- **R4b：薄 GUI**。选择 Asset/Run/Instance/Evidence 中当前故事需要的一个或少量视图；真实数据、稳定链接、空态和未知态优先。
- **R4c：可选 LUI/Meta**。自然语言管理实测有益才引入，独立 Profile/HOME，经相同服务写入。MG06/MG08 只能覆盖已可用的局部能力；完整条件见 `08` 的 R5 前置依赖。
- **R4d：按需业务会话**。真实长驻故事才引入稳定 Binding/Invocation、流与原生历史；Meta Session 与业务 Session 分开。

**交付与 G-R4**：选定入口完成同一真实故事，来源、修改和 unknown 可查，能找到原始资产及 Session，未接能力显示未交付。CLI 与已选择的 GUI 共用逻辑；只有 Meta 已启用时才要求其与其他入口一致。GUI、Meta、业务会话和四个视图不要求同时建齐。

### R5｜逐项产品能力扩展

按独立痛点选择一条链：新建/导入 Agent；四类 Hub 与 MCP 真实组合；反馈/批量评测；不可变 HarnessVersion 与后续 Session 启用回退；已发布父版的变体谱系；多人 Session/Schedule 隔离；容量驱动的运维。不同链互不自动成为前置门槛。

**交付条件**：所选故事的完整依赖可用，POC 和业务行为有真实证据，收益、失败恢复与限制可说明。MG06 完整任务依赖 AG06/AG07；MG08 完整任务依赖所列四类 Hub、MCP04 及发布后真实绑定/调用。完整产品变体依赖已发布父版，研究对照覆盖不等于任务完成。具体任务映射由 [08](08_112项任务追溯矩阵.md)引用本章。

## 3. 参考时间盒

| 时间盒 | 可选聚焦 | 延迟或停止条件 |
|---|---|---|
| 第 1–2 周 | R0：一项真实输入的比较、回归和 Decision；变体仅在选定假设下试验 | 来源、环境或证据不可信则继续 R0 |
| 第 3–4 周 | R1：一个高频窄工具，记录使用成本 | 没有收益则停止工具化 |
| 第 5–6 周 | R2：真实对象关系、恢复和是否需要数据库的判断 | 没有事务需求则保留文件 |
| 第 7–9 周 | R3：一条问题到改进的工具闭环 | 原生接口不足则缩为 Run 证据路径并记录限制 |
| 第 10–12 周 | R4：有需求时选择一条 API/GUI 或 LUI 探针 | 未出现消费者则留在自用工具 |
| 之后 | 按痛点扩展 R4 或一条 R5 故事 | 不按周数承诺全平台 |

这是资源假设，不是工期承诺或所有任务的顺序。选择和证据记录方法见 [12](12_阶段决策与实际执行协议.md)。

## 4. 决策记录与停止条件

必要信息包括实际操作、问题、已有证据、唯一写者、最小修改、比较方法、恢复、实测限制和下一步；可引用已有 Experiment、Run、验收矩阵或任务记录，不要求另建工作卡、编号或审批台账。

选择 Variant、Trace B、数据库、MCP、Meta 或多用户后，分别执行 `07` 对应探针；未选分支不运行其 Gate。停止结论允许 `adopt/continue/reject/inconclusive`。工具增加维护成本、变体严重退化、LUI 更易选错目标或扩展没有收益时，应保留证据并撤回该扩展。

本路线不改变根级 Research Mode，不自动授权平台开发、提交推送或业务发布，也不新增 PA 路径或生产门禁。
