# 12｜阶段决策与实际执行协议

本章说明怎样选择下一项工作和保存依据；R0–R5 定义、进入/退出条件只在 [05](05_实施路线与迭代计划.md)维护。当前执行遵循[根级 AGENTS.md](../../AGENTS.md)。

## 1. 从真实问题开始

1. 明确使用者、输入、预期结果、障碍和原始证据，检查工作树及验收矩阵。
2. 找到唯一资产、Case、运行事实和写入口，选定本次情境及纳入的可选分支。
3. 引用 `05` 的相关条件与 `08` 的任务依赖，选择最小切片；未选择的能力不计作缺陷或门槛。
4. 先验证已知假设，再决定是否工具化或抽取服务。使用现有记录，不机械生成新工作卡或审批台账。

## 2. 比较运行与判断

冻结 Baseline/Candidate、输入、评审器、镜像、模型与工具，并按 [03](03_存储架构与数据契约.md#comparison-environment)检查每个 Case 的外部后端、复位/隔离、执行顺序和证据。来源或口径改变后重跑受影响比较；结果不能为了更好看而覆盖或降标准。

实际 Run 分别保存来源、dirty 状态、观察、回归和限制。现有比较布尔标记不是因果证明；不可控环境只作观察比较。由人将结论写入已有 Decision，允许 `adopt/continue/reject/inconclusive`。实际装载必须用新进程或新 Session 核查，源码保存不能代替行为验证。

## 3. 按需求触发扩展

| 真实触发事实 | 应选择的验证 | 未触发时 |
|---|---|---|
| 多次重复手工操作或来源错误 | `05` R1 的使用成本比较、T05/T15 | 继续使用现有 CLI |
| 资源/组件差异是研究假设 | T03、W05/W06 及 `03` 比较环境 | 不增加变体门槛 |
| 多入口、并发事务或重启后需查操作 | 数据关系/恢复、T07、W12 | 保留简单状态文件 |
| 原生读取不足且需要平台持久 ACK | `03` Trace B、原生重放与采集故障试验 | 原生读取 A；不宣称 TR02 完整交付 |
| 自然语言管理预期降低成本 | Meta 探针、已启用入口的一致性 T11/UI-03 | 不要求 Meta 通过 |
| 组合工具有真实复用需求 | MCP 连接/调用、两步执行 T12，再考虑画布 | 不建 Composer；MG08 仅可声称局部覆盖 |
| 长期业务版本替换或第二位用户 | `04` W7/多用户边界、T13/T17 | 不建发布治理或多租户体系 |

## 4. 条件依赖的实际例子

一个普通 Harness 改进完成 W01–W04 后，如有重复操作痛点可转 W07/W08，不必先执行变体 W05/W06。选择变体故事时，才核查其资源、同口径与外部状态条件。

只选择 GUI 的故事，按 R4a/R4b 验证同一真实后端路径；没有 Meta 不需要 T11。选择管理对话时可先用已有能力作局部切片，但完整 MG06/MG08 仍需 `08` 列出的创建/导入或 Hub/组合依赖。

## 5. 保存决策与停止扩建

记录问题、纳入范围、原始依据、唯一事实源、最小修改、运行方法、收益、新增维护成本、限制与下一步。优先引用既有 Experiment、Run、Decision 或任务文档，不同时维护多种投影。

有收益且证据足够时采纳当前变化；有问题继续；没有收益拒绝扩展；证据不足就保持不确定。阶段转换不自动触发平台开发、业务发布、提交推送或外部写入。
