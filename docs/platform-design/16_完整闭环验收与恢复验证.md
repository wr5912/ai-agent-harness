## 验收计划与边界

算力验收先采用不改变业务语义的 A/A 比较：固定同一父版并完整派生，两个 Case、每侧两次独立 Run。它验证平台的真实比较流程和拒绝无依据优化结论的行为，不用于证明某个优化策略已降低算力。业务模型保持 `deepseek-flash/off`，平台管理助手为 `deepseek-flash/max`。

本次使用本机系统 DSH、既有标准容器镜像和真实模型服务；业务上游使用基本模拟数据。正式入口为 `/hep/`。原始验收材料保存在本机 `/tmp/hep-e2e-20261016/`；普通报告不包含凭据。旧 Run、旧失败结果与迁移前证据保持不变。

## 实机发现与整改

### 首次实例 HOME 的目录属主

实际创建全新评测实例时，`home-init` 在 `/var/lib/dsh/profiles/web` 报 `EACCES`。新的 HOME 使用目录挂载，Docker 在挂载 `profiles/node_modules` 子卷前先以 root 创建缺失的 `profiles`；旧 HOME 已有目录，因此原迁移验收未覆盖此问题。启动器现在在 Compose 创建容器前预建目录，保持调用用户属主。117 项生命周期回归通过；原失败 Run `run-c4e99fb8-8a82-4439-8cbc-f4f4aa364218` 保留，后续四个独立新 Run 全部完成。已有失败 HOME 的属主不被静默更改；同名重试在 Compose 前明确报告不可写目录和保留数据后修复权限的要求，实机确认原 HOME 保留。

### 缓存与输入 token 的资源口径

DSH 锁定版本 `21638c563` 的 `TokenUsage.inputTokens` 仅计未缓存输入，缓存桶与它互不重叠。本轮相同摘要任务分别记录 `240 + 2176`、`496 + 1920`，完整输入均为 2416；旧比较表把缓存差异显示为输入变长。现在按 DSH 的准确总量与分桶合同计算完整输入，拒绝负数、非整数、溢出与分桶矛盾，无法确定时显示未知；reasoning 属于输出，不重复相加。界面明确标注“输入 token（含缓存）”。同一批原始轨迹回读后，两侧各 Case 等权输入均为 2398、变化 0%，原始 Run 未改写。

### 程序与数据同时恢复

恢复 HOME 中的生成链接仍指向旧程序目录时，原 prepare 拒绝重建，MCP 身份校验也可能在换链后失去原关系。现在仅重建已知程序生成的 bundle 和研究 Skill 链接，在换链前核对原生 MCP 身份；普通文件、目录、不明链接和不相关身份仍保留并报错。27 项启动器回归通过，已用独立程序副本实际 prepare、登录并读取原持久数据。共享部署制品摘要保持不变。

### 管理助手的来源、提案与完成回执

历史特性将 `evaluation/observations.md` 记为 Experiment 相对路径，详情却按数据根解析，误报证据缺失；模型转而阅读程序源码寻找原因。现在历史引用按所属版本解释，新保存统一数据根相对路径；助手有专用的研究来源读取动作，特性任务只暴露 Skill 与平台工具。普通版本派生另提供当前完整 Candidate 的可恢复引用，明确祖先 `baseline_ref` 不能代替当前父版；尚未提交或已编辑但未固定的 Candidate 不提供可用引用。

真实确认写入之后，旧工具回执同时包含 `state=completed/result.ok=true` 和预览中的 `requires_confirmation=true`；工具说明又称“写操作返回待确认提案”，与实际等待确认和执行结束才返回的行为矛盾。模型据此误述“尚未保存”。结算回执现在仅返回实际动作、状态、结果或错误，工具说明与 Skill 同步真实完成合同；Session 中的提案预览仍保留供界面回看。取消、失败、执行状态未知及重复确认继续分别处理。MCP 组合草稿也在产生确认卡前使用原有配置解析器校验，避免把展示用的 graph 包装误当可保存配置。
