## 长期能力演进与当前执行边界

本项目的长期方向是：**Harness 工程研究验证 → 有价值的自用工具 → 可信数据体系 → 可复验的工具闭环 → 按需构建 AI 原生智能体运行管理平台 → 持续演进**。研究是当前能力阶段，不预设未来产品必须永久依赖独立的外部“研究系统”；长期首先保留任务、评估标准、验收数据与真实证据，核心 Harness 资产及已验证的工具能力尽量连续演进；当前仍坚持 DSH-only，不预建多 Runtime 统一抽象。

长期演进采用 `R0–R5` 标签，**唯一阶段定义**见 [`docs/项目能力演进原则.md`](docs/项目能力演进原则.md)。该路线不是固定工期、全局审批门禁或允许提前建设基础设施的命令。当前工作模式仍为 **Research Mode**，所有既有简洁优先、单一事实源、精准修改、研究证据与安全底线继续生效。

- 112 项未来产品任务及 `G1a/G1b/G2/G3` 仅说明目标产品的需求优先级，不自动成为当前施工清单；`R0–R5` 也不同于现有 `PA-xx` 项目验收路径和上游规范的生产交付 `R1/R2/R3` 分级。
- 每项工作先确认当前真实研究问题或自用痛点、已有入口、唯一写入事实、最小改动和可核查的成功/失败/未知证据。优先复用现有 CLI、DSH 与研究资产，不仅因未来可能平台化而建设数据库、服务、UI 或治理设施。
- 未来数据存储和代码组织形式可以调整，但不能对同一 Candidate、Case、研究 Decision 或 DSH 会话事件保留两个可编辑事实源。迁移写入职责时必须明确新旧入口的交接与真实恢复结果。
- 研究采纳、Research Release、平台正式发布、业务启用是不同事实。项目当前不因研究通过就自动发布或切流量。
- R1–R5 的扩展是否有价值由真实消费者、端到端证据和新增复杂度决定；收益不足允许停留、回退或删除新增抽象。正式扩大项目使命须经维护者明确确认并同步修订当前合同，不能由阶段标签自动发生。
