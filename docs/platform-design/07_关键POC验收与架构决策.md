# 07｜关键 POC、验收基准、ADR 与风险

## 1. 本方案只按实验证据推进

本套设计提供架构方法，不替代实机验证。原任务清单是目标产品的期望行为；它没有证明锁定 DSH 版本暴露所有 Session/feedback/cancel API、跨容器 Trace 持久 ACK、业务发布或组合 Gateway。本章把未知显式转为**验证项**和必要时的“功能范围决策”。

本次仅整改文档，下列 T01–T17 未实际运行，不能记为 pass。历史相关实验的局部结论也不自动完成这些 POC。仅执行选定故事需要的探针，阶段条件引用 [05](05_实施路线与迭代计划.md)。

## 2. 按风险排序的可反驳 POC

| POC | 最小真实操作 | 通过证据 | 未通过如何处理 | 引入阶段 |
|---|---|---|---|---|
| T01 来源锁定 | 修改 Git 工作树后，旧评测仍使用原固定来源 | 源 SHA/摘要与实际挂载一致，旧 Run 不漂移 | 修 SourceResolver/冻结策略 | R0 |
| T02 评测同口径 | 一项真实输入的 Baseline/Candidate 比较，按 `03` 核验后端初始状态 | 两个原始 Run、口径/来源、复位或隔离证据、执行顺序；拟作因果结论时检查顺序效应 | 修实际阻断根因；后端不可控则仅观察比较，不自动归责 dsh-eval | R0 |
| T03 变体小样本（仅选定时） | 同 Case 在两种资源/组件组合运行 | 任务质量+资源证据、缺测和适用范围 | 未证实等效就 reject/inconclusive | 选定变体故事时 |
| T04 HOME 隔离 | 两个 DSH 实例、容器删除/重建 | 独立 HOME、互不串 Session、资产只读、保留历史 | 修 Instance Adapter，不先建管理 UI | R1/R2 |
| T05 工具收益 | 同一研究工作流人工 vs 统一 CLI | 手工步骤/误操作/时间的客观比较 | 无收益停止抽象 | R1 |
| T06 持久关系 | 从历史 Run 定位原 Instance/DSH Session | ID/Owner/Source 可核查、重启后引用不串 | 补最小外部状态/引用，不先全量投影 | R2 |
| T07 PG 必要性 | 两种真实写路径在文件/SQLite 方案竞争或恢复 | 现存故障/查询痛点与 PG 成本有基线记录 | 没有收益则不引库 | R2 |
| T08 工具闭环 | 一条 Trace/Run 失败→确认 Case→新 Eval→Decision | 只有一个 Case 编辑源，原始引用保留 | 回退到手动但可复验的流程 | R3 |
| T09 原生 Session Query | 创建/继续/刷新 Session、部分中断 | 原生持久记录可重读，缺失 delta 明示 | 缩范围或窄只读桥，先不建事件湖 | R2/R4 |
| T10 修改操作对账 | Docker 已执行但服务在回包前退出 | 同 request_key/Operation 查询，无法确认 unknown | 禁止重试高副作用工具 | R4 |
| T11 GUI/Meta 一致性（仅 Meta 启用时） | 同一管理任务两入口调用 | 相同来源校验、动作阶段、证据链接 | 禁止 AI 绕过 Service | R4 |
| T12 MCP 两步 Tool | 两个实际 MCP Server 工具 → 单组合 Tool | Gateway tools/list+tools/call，外部 DSH 发现并调用 | 不做画布，先解决 Schema/鉴权/超时 | R5 |
| T13 发布/启用分离 | 发布 HarnessVersion 后未切换业务，新会话确认后再切换 | published≠enabled；旧 Session 来源不变 | 不开放发布/变体派生页面 | R5 |
| T14 备份实复 | Git + 各 DSH HOME + 后期 PG/制品恢复 | 历史 Run/Session/Operation 能在隔离环境打开 | “备份存在”仍为未验收 | R2 起渐进 |
| T15 真实使用收益 | 在一周实际工作中反复使用同一个新工具/页面 | 节省步骤/时间或显著降低选错目标，且无质量退步 | 删除或退回薄工具，不继续铺平台 | R1/R4 |
| T16 Profile/种子装载 | 检查目标 Profile/Preset/bundle 与覆盖，分别恢复新卷和新 Session | 声明、实际 profile、Candidate 种子与行为可核对，开发身份未被替换 | 修真实装载路径，不以保存配置证明生效 | 选定相关接入时 |
| T17 双用户 Session/Schedule | 同 Agent 下两个用户从 UI/Remote 交叉操作，检查模型工具、到期投递和重启 | `04` 所列全部已开放入口服务端归属一致，不能越权或串投递 | 不开放共享 Host；按用户隔离 Host/HOME 并验证 Gateway 路由 | 选定多人故事时 |

每条 POC 的结果可以是 **pass / fail / inconclusive / not-run**；必须写出证据路径、锁定镜像/依赖、运行环境、失败/未知，不能因“架构图通过审阅”标成 pass。

## 3. TR02/TR03 的验证与范围决策

Trace 路线、持久衍生副本许可与写权统一引用 [03 的 Trace 合同](03_存储架构与数据契约.md#trace-contract)，本章不另建规则。T09 先检验原生读取；只有已选择 B 才验证 ACK、游标、去重、补取和崩溃恢复。原生读取 A 不构成 TR02 完整交付；B 允许合适存储持有只读衍生副本，但需要实际覆盖证据。

完整要求尚不能实现时，记录未交付或经需求所有者确认的阶段范围，不能删要求后标绿。MCP 两步 POC 属于完整 MG08 的前置之一，不要求普通研究故事先通过它。

## 4. 决策记录（ADR）——默认选项与改变触发事实

| ADR | 当前默认 | 允许改变的实证信号 |
|---|---|---|
| ADR-01 能力演进 | 按 `05` 的选定故事、条件分支逐步复用能力 | 仓库拆分确实减少依赖/发布成本，且无重复写源 |
| ADR-02 研究事实 | Git Experiment/Candidate/Case/Run 仍为当前维护事实 | 正式资产 Service 接管唯一写权，完成校验和旧入口只读切换 |
| ADR-03 Runtime | DSH-only、锁定镜像/插件、原生 SessionPersistence | 锁定 DSH 的升级与装载兼容经 POC 验证；引入其他 Runtime 需先明确项目使命变更 |
| ADR-04 数据库 | R0/R1 无 PG 强制要求；R2 先稳定 ID | 多入口并发/重启事务/跨对象查询真实受益才推荐 PG |
| ADR-05 Trace | 按 `03` 默认验证 A，不建设全量事件中心 | 已选持久 ACK 需求且原生不足时验证 B，存储许可与权威仍以 `03` 为准 |
| ADR-06 工具边界 | 优先组合现有 CLI/函数，避免微服务 | 第二消费者、部署故障边界/扩容实证要求拆 Service |
| ADR-07 LUI | 目标体验，但不是研究前置条件 | 管理自然语言场景重复发生，LUI 提升真实效率/正确率 |
| ADR-08 Variant | 按任务/预算/等效门槛独立验证 | 真实任务族证明标准方案可以复用，才抽模板/自动路由 |
| ADR-09 MCP | 先单工具、固定二工具 POC，再 Gateway | 组合真实有益且需反复编辑时才做画布和不可变版本 |
| ADR-10 部署 | 单机受控内网、独立 HOME，必要时 PG | 容量/可靠性实测不足再扩多宿主、队列或 OTEL/分析系统 |
| ADR-11 产品发布 | Research adopt、Release、published、enabled 分离 | 不能以简化为由让研究 Decision 自动触发生产行为 |
| ADR-12 最小安全 | 不在模型上下文/日志泄漏凭据，禁止未经授权破坏性动作 | 多人对外服务触发服务端认证、session 所有权和定时任务验证 |

## 5. 失败场景与恢复矩阵

| 故障 | 权威事实还在哪里 | 正确行为 | 不正确行为 |
|---|---|---|---|
| Candidate 修改中断 | Git 工作树/已冻结摘要 | 按 diff 找到剩余修改；人工确认后继续 | 复制一份“最新 Candidate”到 PG 继续编辑 |
| 评测被中断 | 已产生的 Run/原生 Session | 保留完成/失败/未运行项和来源，必要时新 Run 重测 | 用新结果覆盖旧 Run |
| 容器创建成功但客户端超时 | Docker 实际状态，外部操作记录可能未知 | 以精确 owner/容器/来源核对，不能确认 unknown | 直接再建同名容器 |
| DSH Session 存在但 UI 丢链接 | DSH 原生日志 | 从 owner+Runtime+Session 恢复只读历史 | 生成一个新空会话掩盖丢失 |
| Meta 工具重复调用 | Operation 唯一 request_key（如已引入） | 同一回执与状态对账 | 将相同修改执行两次 |
| 下游 MCP 写操作执行结果不明 | Server 回执/可查询业务状态 | unknown，人工或安全对账 | 同参数自动补发高副作用工具 |
| PG 不可用（如已引入） | 已提交状态是否成功需要 DB 重试查询 | 停止受控修改，恢复后按 operation ID 核查 | 写本地可编辑影子 DB 补账 |
| DSH 原生 Query 缺事件 | 原始可读取部分与可靠覆盖范围 | 标注缺口、研究 Schema/最小探针 | UI 虚构父子 Span/完整 Trace |
| 撤回已发布版本 | 不可变资产/Session 历史 | 停止新派生/新会话路由，保留旧引用 | 删除旧版本资产和历史会话 |

## 6. 工程质量最低标准（不是一整套生产治理体系）

- 当前工具：稳定输入/输出、错误码、来源摘要、最小重跑示例、少量合同测试与真实任务验收。
- R2 以后：ID 唯一作用域、恢复/删除语义、来源不可变证明、状态时戳、备份复原。
- R3：每个跨工具步骤有真实来源，失败能定位，避免重复 Candidate/Case 写者。
- R4：修改型动作都可预览/确认/幂等/对账；Meta 没有自由 Docker/SQL 凭据；来源变化拒绝旧确认。
- R5：只有产品真实多人/长驻/第三方工具暴露时再实施所需服务端认证/访问隔离/持久采集与运维流程。

## 7. 风险登记（列优先信号，不新建管理平台）

| 风险 | 早期可观察信号 | 最小措施 |
|---|---|---|
| DSH 预览版 API/Session 变化 | 升级后 Session Query/模型选择/事件 schema 失败 | 镜像/依赖锁定 + 独立兼容测试 |
| 评测证据不可靠 | 相同 Case 反复结果差异无法解释 | 固定来源/评审器/资源条件，保留样本数与不可比 |
| 工具链过度抽象 | 一人用却出现多个服务/双模式 | 删除未被调用的层，保留现有 CLI |
| Git 与 PG 双写 | 同一 Candidate/Case 可在两处修改 | 单次迁移写权，旧入口只读或委托 |
| Trace 过度承诺 | Session 中断后 UI 仍显示“完整” | 显示覆盖/未知，TR02 另立验收范围 |
| 多变体伪等效 | 只比较平均分，关键 Case 大退步 | 事前业务质量下限+退化红线+资源证据 |
| 平台首屏沦为聊天壳 | LUI 答“完成”但没有操作回执 | 强制共用 Service/真实 ID/证据链 |
| MCP 画布先于 Gateway | 拖线漂亮，但发布后 tools/call 不通 | 固定两步 POC，真实调用再做画布 |
| 多用户共享 HOME 串数据 | 猜 ID 可以读取他人 Session | G2 开放前做服务端归属验证，必要时独立 HOME |

## 8. 记录所选故事的决策

引用原始证据，记录故事范围、实际镜像/依赖、需要的 POC 及结果、恢复路径、收益、复杂度、限制与下一步。未选变体/Meta/MCP 不增加对应门槛；阶段条件只在 `05` 定义。已有 Experiment 或任务记录足够时直接引用，不要求创建阶段审批单或追踪数据库。
