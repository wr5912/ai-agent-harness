# 项目对抗审查与实机验收（2026-10-16）

本轮承接个人工作台与决策样本实现，基准为 `f0aeca73166d3902ff5d727d43dfce6b86ef8c7e` 及 `feat/PLATFORM-personal-workbench-datasets` 的未提交工作树。审查当前代码、配置、技能、智能体资产、评测与文档的接口关系，以实际用户任务能否可靠完成作为判断依据。历史 Run 保留原始事实，Mock 只代表外部模拟边界。

## 计划与判断方法

1. 核对分支、远端、部署进程、原生 DSH、标准镜像、模型与 MCP 来源；保护既有工作树及共享实例。
2. 并行审查三条主链：轨迹到决策样本、个人研究工作台、DSH 运行与 MCP 编排。另核对开发指令、当前设计与已实现主张。尝试反例，区分确定缺陷、设计建议和未验证内容。
3. 在正式平台 URL 进行浏览器与真实 RPC 验收：六页、样本抽取与保存回读/导出、Case 与运行、资产差异/比较/Decision、实例状态、MCP 只读编排；使用真实模型验证智能体行为与工具调用，不以监听或 HTTP 200 替代业务结果。
4. 对已确认问题先记录触发条件和共同根因，修正直接相关入口与消费者，增加能复现问题的必要回归，再重建、装载和复测。
5. 检查现有测试、仓库/Experiment 合同、链接、敏感信息与完整提交差异；提交并推送当前功能分支，独立核验远端 SHA 和工作树。此次未要求新 Tag。

受影响验收路径为 PA-01/03/04/05/06/08/10/12。Research Release 复现、全部历史实验的重新运行、模型训练效果及真实外部安全运营不是本轮可推定的结论。

## 覆盖和结论边界

审查深入读取当前平台六页、共享 RPC 与原生助手、轨迹/样本、Case、版本资产、实例生命周期、MCP 及其编排，追到 DSH 来源、评测驱动、Run 封存/比较及对应测试。读取开发指令、项目技能适用边界、当前设计入口和需求主张；业务侧核对当前主线 EXP021 的装载、Guard、MCP 目录及现有三份真实候选内容。历史实验与记录只沿当前主张追溯，没有逐条重读全部历史 Run 或重新执行全部历史 Case。

本轮不宣称全项目每份历史资产均无缺陷。未重新验收 ASR/TTS、周期调度的全部行为、策略/应急实际写操作、Research Release 复现、模型训练或真实 SOC 业务效果。EXP021 首步仍可见部分会被硬 Guard 拒绝的工具 schema；本轮遵守不改业务 Harness 的接入原则，记录可见目录与执行边界的差别，没有把 schema 可见认定为执行越权。

来源核对比较初始化和封存两个时点，不能发现期间改变后恢复的短暂漂移。SIGKILL 和宿主崩溃不属于能执行清理的取消信号。当前 Mock 为本机模拟环境，报告仍可能返回宿主回环地址；本机下载验证不代表远程浏览器报告访问合同。
