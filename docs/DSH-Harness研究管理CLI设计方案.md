# DSH Harness 研究管理 CLI 设计方案

> 状态：当前已有若干本地 CLI 和一个只读查询原型；本文只描述下一步如何把它们收敛为简单的研究入口。管理平台、常驻服务和 Web 管理后台不在当前范围。

## 1. 为什么先做 CLI

本项目服务单个开发者在一个仓库内研究 Harness。当前真正需要的是：选定来源、启动 DSH、记录改动、保存 Run、比较观察。它们都是本地、低并发、Git 驱动的操作，用几个可组合的 CLI 已经足够。

只有出现已验证的多人协作、长任务调度或跨机器执行瓶颈时，才重新判断是否需要平台。不能因为“以后可能做平台”就现在引入数据库、账户体系、审批流、任务队列、状态服务或 Web 后台。

## 2. 当前已有入口

| 入口 | 当前用途 | 边界 |
|---|---|---|
| `dsh-dev` | 解析 Experiment，构建镜像，启动、查看和停止本地 DSH 实例 | 不判断 Harness 效果 |
| `source_contract.py` | 把来源解析成 Agent、Preset 和挂载计划 | 当前只支持 `experiment:<id>` |
| `mutation-receipt.py` | 记录变更前后资产摘要和差异 | 不替代 Git 或人工复核 |
| `run_record.py` | 创建、追加和封存 Research Run | 不执行任务，不给研究结论打分 |
| `validate_repository.py` | 检查仓库、Experiment 和 Research Release 的确定性合同 | 退出码 `0` 不表示假设成立 |
| `validate_experiment.py` | 检查一个 Experiment 的最小研究记录 | 不要求固定 Case 数或生产门禁 |
| `plugins/asset-query-cli/` | 只读列出 DSH 资产的原型 | 不是管理平台，也不执行写操作 |

这些入口可以继续各自演进，不急于包成一个总命令。只有重复参数或重复解析已经造成真实维护成本时，才抽取共享模块。

## 3. 最小研究闭环

```text
选择 Experiment
      ↓
dsh-dev plan / up
      ↓
修改 Candidate + mutation receipt
      ↓
新容器、新 Session 观察
      ↓
run_record 记录输入、结果和限制
      ↓
Decision：adopt / continue / reject / inconclusive
      └──────────────→ 可选 Research Release
```

Git 是研究源码和版本历史的主要事实源。`runs/` 保存无法只由源码还原的执行观察；仓库外的 DSH_HOME 保存 Session、设置、附件和缓存。这三类内容不能混在一起，也不需要为此增加中心数据库。

## 4. 后续 CLI 的选择标准

新增命令前先回答：

1. 当前是否至少有两个真实操作反复需要它？
2. 现有命令或短脚本是否已经足够？
3. 它是否能减少来源选错、结果丢失或不可复现，而不是只增加抽象？
4. 输出是否能直接被人读懂，并清楚区分成功、失败和未知？
5. 删除这个命令后，是否会失去当前研究能力？

只有答案支持新增时才实现。优先扩展 owning CLI，不创建平行平台。

可能的后续能力只有两项已知缺口：

- `release:<id>` 的解析与只读装载；
- 对两个 Run 的简洁对比视图。

它们仍应先以本地命令实现和验证。未出现实际需求前，不规划发布审批、自动优化、分布式 Runner、操作状态卷或多租户管理。

## 5. 数据和安全边界

- 不提交秘钥；模型和 MCP 凭据只在运行时注入。
- 外部归档先用 `legacy-asset-intake` 只读检查，不自动执行其中内容。
- CLI 不进行用户未授权的提交、推送、打 Tag、删除、覆盖、发布或外部写入。
- 命令如实报告失败和未知状态，不把目录存在、容器启动或 HTTP `200` 写成研究成功。
- Session、缓存、附件和整个 `$DSH_HOME` 不进入 Git、Candidate 或 Research Release。

具体业务 Harness 的工具约束、Guard 或审批可以作为实验变量，但不要求 CLI 建设一套通用权限平台。

## 6. 何时重新评估平台化

只有下列问题在真实使用中重复出现，并且本地 CLI 无法合理解决时，才重新提出平台方案：

- 多名研究者需要同时编辑同一资产并频繁冲突；
- 大量长时间 Run 需要跨机器排队、恢复和调度；
- 研究资产数量使本地索引明显不可用；
- 需要给非开发者提供稳定的只读结果界面。

届时先记录瓶颈、使用频率和最小目标，再决定是否需要数据库、服务或 Web。平台化是新的工程阶段，不是 Research Mode 的默认终点。
