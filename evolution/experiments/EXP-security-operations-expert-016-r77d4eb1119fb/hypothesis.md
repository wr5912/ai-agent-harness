# 研究假设

Baseline 为 `git:047bb6a0202864a58755f84c22e5a01e2021d209`，继承 EXP-015-r904bdcd81005 的业务 Candidate。语音插件以既有 TypeScript 源码 `bafd268ba4f617614b2e69743e55325e44062a4a` 的 0.0.3 实现替换旧生成物；仅改造自动播报、传输合同、设置与直接相关验证，保留手动整条朗读、语音输入和唤醒功能。

每次主 LLM Call 正常完成且有可见正文时，插件用独立辅助调用生成默认约 30 字的口语摘要，包括工具调用前的正文。插件设置页配置目标字数、提示词和已配置模型；默认跟随该次主调用模型。推理、纯工具、失败、打断或长度终止不触发摘要。辅助调用不带 Session 或工具，摘要不会再次触发自身。

DSH 原生 Session 事件没有适合本功能的忽略持久化标志，历史事件解码也限制已知事件类型。因此将 `speech-summary` 放在插件的 `voiceMode.follow` 逻辑流，与原生 `session.follow` 共用现有 `/api/remote.mux` 连接，不修改 Runtime，不写入 Session 历史。摘要事件文字原样送入 TTS；下行音频和语音状态也迁移到此连接。未安装插件或会话自动播报关闭时不做额外摘要调用。

同一会话串行完成摘要与合成；新回合、打断、关闭播报、切换会话、断线和卸载取消未完成任务，并丢弃忽略取消的迟到结果。同回合下一步不取消前一条。辅助失败只提示本次跳过，主回合继续；重连仅接收后续事件。

以 [评估唯一事实源](../../../agents/security-operations-expert/evaluation.md) 的 U-VOICE-002、U-VOICE-003 比较。先验证来源判定、队列、配置边界与取消，再在锁定标准镜像中用确定性模型和 PCM 音调验证实际设置页、共享连接、TTS 输入、浏览器解码与播放、历史冷加载及插件缺席/卸载。它们证明技术链路，不能证明真实模型保真、字数达成率、额外费用或真实语音听感；取得实际模型和语音环境后继续验证研究价值。
