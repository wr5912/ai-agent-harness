# EXP019 观察

2026-10-13。本次验证范围是摘要配置入口、MCP 目录与分组资源读取，不扩大为安全运营业务全量验收。来源与预期见[假设](../hypothesis.md)。最终技术 Run 为 [run-cbb0ac34-b034-45a3-a258-588dcfa33444](../runs/run-cbb0ac34-b034-45a3-a258-588dcfa33444/report.md)，冻结了实际 Candidate 的文件摘要、固定 Baseline 和 Git dirty 状态。

## 根因与结果

语音插件已有摘要模型、目标字数和提示词表单，但只注册了设置页，没有注册插件管理页卡片及其客户端依赖。EXP019 注册“语音摘要性播报”并复用原表单和持久化接口。浏览器将已配置的 Local Qwen 模型、45 字目标和自定义提示词保存，刷新后逐项核对，再恢复原模型、提示词和默认 30 字。语音后端及摘要队列与固定 EXP018 完全一致。

旧 MCP 分组页未发现服务时只显示已保存的工具名，“工具与资源”页显示完整上游目录；它们的数量含义不同。EXP019 让两处使用同一发现结果，展开服务器时自动发现，分别显示发现数量和已选数量，保留当前未发现的历史选择。读取分页直到结束，拒绝重复游标；发现失败标记“未确认”，不写成零个。

实际 sec-ops 在两处均发现 165 个工具、0 个资源、0 个资源模板。管理页展示服务完整目录，不用智能体的 15 个故障取证工具白名单截断目录。分组页已改为“工具与资源分组”，选择区已改为“选择工具与资源”。

工具通过 `tools/call` 执行命名操作并返回结果；资源通过 `resources/read` 按 URI 读取数据；资源模板描述含参数的 URI，先代入明确参数再读取。资源也可交给智能体使用：DSH 将发现和读取动作封装为 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` 三个原生工具。协议依据为 [MCP Resources 规范](https://modelcontextprotocol.io/specification/2025-06-18/server/resources)。

本次资源分组持久化工具名、资源 URI 和资源模板，分组链接仅列出所选项目，并转发实际读取。Guard 与故障取证子智能体原工具过滤器会阻止原生资源工具，因此同步补齐这三个工具的可见性与许可；其余业务工具、业务路由和专用子智能体限制不变。

## 迭代失败与限制

初次来源登记沿用了 EXP018 的 Profile 路径，来源合同拒绝启动；改为 EXP019 路径后重新验证并启动。语音客户端结构测试的依赖预期未加入插件管理模块，首次失败后同步预期；完整回归通过。浏览器探针首次未切换到 sec-ops，随后因切换 tab 后服务器折叠而找不到按钮；修正探针选择器后在真实页面重复执行通过。

依赖目录软链接导致语音生成物带入另一工作树的路径。改用本地忽略的依赖目录重新执行原构建器，排除这类无语义差异；语音后端生成物与父版一致。容器根文件系统只读，探针复制被拒绝；改用标准输入执行，没有放宽容器配置。

较早的 [run-3bd241f1-75da-46a7-9ebc-0aa9e6f34f9a](../runs/run-3bd241f1-75da-46a7-9ebc-0aa9e6f34f9a/report.md) 在资源许可修订前冻结输入，没有形成业务 Trial，取消封存。最终 Run 使用稳定资产重新验证技术路径；两项语音业务 Case 只取得上述局部证据，因此保留 `inconclusive`。

本次未执行真实模型主动选择资源的业务回合、真实语音设备听感、全部安全运营 Case、评分复核或 Research Release 复现。真实 sec-ops 当前不提供资源，资源读取使用明确标识的受控外部接口。继承 EXP018 的既有研究限制，不把本次插件修复写成全业务通过。
