## 本轮发现并已修复

1. 初始 seed 的威胁分组包含三个工具、资源及模板均为空的成员，`snapshot` 拒绝整个配置，导致 MCP 管理插件不能激活。仅移除了这些未配置成员，保留连接定义与已知真实工具选择，不填造资源 URI。新增测试直接读取实际 seed，经 YAML 解析后调用真实 `snapshot`。
2. Guard 在 resolver 延迟挂载时先返回，漏掉首次 `beginTurn`。实际代码纯内存复现：同一用户明确 DENY，正常分支拒绝 ALLOW，延迟分支错误放行。已把本轮初始化移到延迟分支前；新增测试覆盖首次延迟、挂载后及下一轮更改 ALLOW，并保留未知写和模型确认工具拒绝。
3. 平台威胁 Run 原先只冻结连接 ID。同 ID 改目标会影响后续副作用。现在保存非敏感目标摘要并在阶段及每次原生调用前复核；发现过程中切换地址也拒绝。凭据轮换不改变目标身份。旧 Run 无摘要时可以 `inspect`、下载产物和纯重放已完成阶段，新阶段不得按当前目标补造身份。
4. 新 Agent 的 MCP 分组原先只冻结发现名称和 URI。现在三类发现回执通过标准 `_meta` 返回目标摘要，桥冻结并随工具及资源调用携带；管理器在实际上游调用前核验当前配置。Token 从现有管理插件服务读取，环境仅作兼容回退，不把真实 Token 交给 Python。
5. 认领后取消原先直接终止 Python，跳过失败写回。现在 Node 先分配运行 ID，Python 认领后原子保存身份，取消后等待旧进程退出，再以独立短时限清理同一运行。清理先保存尝试标记；既有 result/fail 请求不改写为相反终态，重复清理不新增写调用。目标漂移时不向新地址补写，明确留下未知状态。
6. 内部 MCP 的 Agent 回环地址也存在站点前缀遗漏，已与威胁分组一样使用原生 `webServer.publicPath`。

助手整改已复核：提案保存组合及版本身份，确认时走固定版本；旧无版本提案拒绝。凭据 URL 的输入、异常和 Session 投影经过统一边界，后端实际业务调用仍使用已有原生凭据来源。

实例重建整改已复核：只从同来源、同实例恢复合同声明且调用环境没有显式提供的变量；显式空值不会被覆盖，异常在停止实例前拒绝，值不写普通状态和日志。
