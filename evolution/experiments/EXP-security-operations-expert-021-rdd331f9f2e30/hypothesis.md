# 归档特性与当前主线融合

直接来源和固定 Git 引用只在 [change.yaml](change.yaml) 维护。主来源为本地语音延迟 EXP020，归档并行来源为带随机后缀的 EXP020；两者不是同一研究。归档摘要、只读接收、清洗与原观察边界见 [来源接收记录](../EXP-security-operations-expert-020-r9d6dc03aa1bb/source-import.md)。

研究假设：归档的运行级 MCP 分组接入、策略端点消歧及原生交付，与当前摘要专用预算、PCM 顺序播放和取消能够在同一新 DSH 实例和 Session 中共存，同时保留原业务 Guard、巡检续查、只读故障取证和受信 Schedule 语义。归档状态仍是 active；它的旧观察不代替本次验证。

从固定主来源完整复制 Candidate，再选择归档功能闭包，逐项处理：

- 保留11个相同的威胁算法、提示词与CSS，不因连接迁移改业务判定。
- 导入MCP组桥及管理器资源能力，统一使用实际WebServer基址；上游的真实HTTP409与标准MCP取消不得丢失。
- 导入策略与应急原生问题及结果交付，恢复归档Guard遗漏的资源、自动研判与跨域边界。
- 保留语音低延迟主线源码、预算和PCM测试，只三方合入基址变化；固定交付正文的语音摘要必须回到真实模型路由。
- 运行级目标发生漂移时拒绝新增副作用；认领后取消应使用同一身份做有界失败清理，不能以杀死进程代替业务收尾。

其余并行来源已按固定主来源的明示继承盘点：019的摘要设置、分页工具资源范围和早期业务能力继续保留；010低算力探索没有等效证据，不能当作已完成end版本，也不把它的约简覆盖当前主线。新版本不切换现有3081实例，不创建Research Release。

最小比较包含两来源的继承差异、当前Candidate的原算法与MCP/策略/语音测试，以及新实例、新Session的真实模型和浏览器操作。业务Case只消费Agent的evaluation.md；真实运行保存来源、dirty状态、完整Candidate摘要和实际轨迹。平台与工具链问题的审查、计划及端到端证据另在[本轮项目审查记录](../../../docs/项目对抗审查与实机验收_2026-10-15.md)维护，不能替代业务Evaluation。

停止条件：无法保留主线预算或业务边界、需要把真实凭据写入证据、发生重复认领/错误目标写回或取消后重复执行时先修复；外部真实服务不可用时限定观察，不把Mock或静态检查当真实上游验收。
