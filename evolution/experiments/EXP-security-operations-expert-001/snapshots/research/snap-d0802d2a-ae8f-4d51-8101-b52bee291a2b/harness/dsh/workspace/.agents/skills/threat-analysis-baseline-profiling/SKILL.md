> 本 Skill 仅由容器内 DSH 装载。来源为旧 Runtime 资产的业务语义迁移；工具名必须由受控 Profile 与 role-tool matrix 实际绑定，Prompt 不授予权限。

## When-to-use

在立靶通过、取得 `ruleId`，且层 2 的实体归一得到无歧义 `entityId` 后使用。

当前若 SOC 尚未提供 `query_baseline`，不要用事件状态历史或全量事件列表代替。直接记录：

```json
{
  "missing": "同规则同实体的历史频次、周期性与外部权威结论",
  "affects": "无法用历史信号生成或区分 H1/H2/H3 具体场景",
  "capability": "H",
  "how_to_close": "提供服务端聚合的 query_baseline"
}
```

接口缺失意味着本角度弃权，不意味着任何场景成立或被排除。

## Workflow

### 步骤 1 — 批量获取数据侧已聚合的基线

复用主调度层取得的结果；单独执行本 skill 时调用：

```text
query_baseline(pairs[], timeRange)
```

`pairs[]` 是相关 `ruleId` 与归一 `entityId` 的组合。一次批量取回，不逐对查询，不全量拉取历史记录自行聚合。

### 步骤 2 — 校验返回语义

| 字段 | 使用方式 |
|---|---|
| `status` | 区分 `OK`、`EMPTY` 和 `ERROR` |
| `sourceHealth` | 判断 `EMPTY` 是否真的表示覆盖窗口内没有记录 |
| `totalCount` | 数据侧计算的总次数 |
| `verdictBreakdown` | 只使用来源明确的人工确认、处置定性或其他外部验证结果 |
| `periodicity` | 数据侧计算的周期模式、典型时点 |
| `firstSeen` / `lastSeen` | 新颖性和持续时间 |
| `recentSamples[]` | 少量可追溯样本，只用于复核，不代表全集 |

`ERROR` 只形成缺口。`EMPTY` 只有在 `sourceHealth` 覆盖完整、时间范围正确时才能表示“该范围内确认没有历史记录”。

### 步骤 3 — 用基线生成或支持具体场景

基线信号的正确作用是**生成或支持**候选，而不是直接定论：

| 观察 | 可以做什么 | 不能做什么 |
|---|---|---|
| 稳定周期、固定身份或固定资产组合 | 生成 H2 合法运维中的计划任务、授权扫描、人工变更、备份等具体场景 | 仅凭周期性宣告本次一定是运维 |
| 与业务日历和资产用途一致的重复模式 | 支持 H3 非攻击性业务或系统行为中的批任务、服务重试等场景 | 仅凭“历史常见”宣告本次一定良性 |
| 覆盖完整且首次出现 | 生成或支持新颖 H1 场景 | 仅凭首次出现宣告攻击成立 |
| 外部权威历史结论高度一致 | 为相似场景提供先验线索 | 把历史事件的结论复制给本次事件 |

**基线不能单独排除 H1。** 攻击者可以利用合法自动化身份、模仿周期行为，重复攻击也会形成历史模式；本次事件仍需用起因、进程、变更记录、行为和结果证据验证。类似地，新颖性本身不证明恶意。

### 步骤 4 — 防止自产结论回声

`verdictBreakdown` 只能接收独立于当前研判链的权威结论，例如人工确认、处置结果或外部调查结果。历史上的智能体自产报告不能反过来作为本次安全事实：否则一次错判会被重复引用并逐渐固化。

若无法确定历史结论来源，按 `UNKNOWN` 处理；仍可使用经数据侧独立计算的次数和周期性，但必须遵守“只能生成或支持场景”的边界。

### 步骤 5 — 输出基线信号

输出至少包含：

- `baseline_status` 和覆盖窗口；
- `signals[]`：每个频次、周期或权威历史结论及其数据来源；
- `supported_scenarios[]`：被生成或支持的具体 `scenario_id`，不直接写最终 verdict；
- `data_gaps[]`：缺失数据、影响和补证方法。

## Verification

本次执行只有在以下条件全部满足时有效：

| # | 检查项 | 验证方式 |
|---|---|---|
| 1 | 未自行做大规模聚合 | `totalCount` 和 `periodicity` 来自服务端，样本数量受限 |
| 2 | `EMPTY` 先校验采集覆盖 | 时间窗、数据源健康和字段覆盖均满足后才使用 |
| 3 | `ERROR` 未充当证据 | 查询失败只进入 `data_gaps` |
| 4 | 历史结论来源独立 | 自产报告或来源未知结论均未进入权威分布 |
| 5 | 基线只关联具体场景 | 每个信号指出支持或生成哪个 `scenario_id`，未直接决定 verdict |
| 6 | 周期性未排除攻击 | 没有“历史规律存在，所以 H1 不成立”的推理 |
| 7 | 新颖性未证明攻击 | 没有“首次出现，所以 H1 成立”的推理 |
| 8 | 缺口可行动 | 每条缺口说明影响与补证方法 |

## ATT&CK 覆盖

本 skill 不绑定 technique。它常帮助构造与 `Discovery`、`Lateral Movement`、`Credential Access`、`Execution` 等表象相似的自动化或业务场景，但 ATT&CK 标签不改变其证据边界。
