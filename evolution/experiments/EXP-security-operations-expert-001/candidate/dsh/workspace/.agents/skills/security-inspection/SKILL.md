# 系统巡检

用户要求正式巡检设备、执行常规/业务/全面巡检、新建巡检任务、查询巡检执行状态、
只读查看巡检任务、结果或 HTML 报告时，使用 `Agent` 委派 `inspection-agent`。

## 委派规则

1. 原样传递用户目标、点名巡检项、分组说法、计划、公开参数和范围；不在主 Agent
   内把分组写死成巡检项列表。
2. 子智能体必须先读取实时目录，按 `groupCode` 展开常规/业务分组，用
   `inputSchema` 补齐各项参数，并把当次具体 `checkIds` 固化为执行或任务快照。
   新增 MCP 巡检项不需要修改本 Skill。
3. 即时巡检允许排除不可用项并说明原因；没有可用项时不执行。计划任务只在命中项
   全部可用且参数完整时生成提案，不静默删项。
4. 子智能体返回的巡检项、`inspectionRunId`、状态、设备事实、业务数值、Schema
   版本和报告标识均来自 MCP；主 Agent 不改写、不二次统计，也不自行计算比例、
   评分、等级、通过/失败或合规结论。
5. Agent 不承载持续进度，创建执行后即返回，用户明确查询时只查询一次当前快照。
   AI Console 只依据规范化 `execute_inspection` 结果投影普通等待消息，由 BFF 后台
   查询终态并以结果接口返回且与本次运行一致的真实 `summary` 和 `detailRoute` 更新
   同一条消息。主 Agent 不自行拼接、改写或在回答文本中伪造链接或自动摘要。
   Runtime/Hook 必须在每次新的即时巡检委派前提供并绑定新的 UUID v4 幂等键；Agent 只原样传递，
   同一次委派重试才复用。
   `replayed=true` 表示既有运行重放，不能表述为本轮新建。
6. 主 Agent 保留“执行技术状态—接口事实—接口已有正式结论—数据缺口—故障分析
   （模型推断）—处置建议（未执行）”分区。接口没有正式结论时明确说明；不展示
   原始 JSON，也不声称访问服务端原始存档。

## 工具与副作用边界

1. 巡检子智能体仅使用 frontmatter 中注册的精确 MCP tools：读实时目录、无副作用
   预校验、启动一次巡检作业（`starts-job`），以及查询任务、进度、公开结果和 HTML 报告元数据。
2. 对话不创建任务草稿，也不直接创建、修改、启停、删除任务或立即执行既有任务。
   提案通过巡检服务校验后，由 AI Console BFF 投影会话归属确认卡；用户点击确认后，
   领域 BFF 执行 Framework 权限校验、actor 注入、幂等创建和审计。
3. 用户要求管理既有任务时，引导前往巡检管理页面。不得把聊天文字“确认”当作创建
   授权，不得依赖 AgentGov 原生 HITL、Bash、文件系统或其它 MCP 绕过巡检服务。
