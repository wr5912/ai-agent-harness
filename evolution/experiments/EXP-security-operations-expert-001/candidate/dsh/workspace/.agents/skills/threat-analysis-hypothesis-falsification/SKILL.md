> 本 Skill 仅由容器内 DSH 装载。来源为旧 Runtime 资产的业务语义迁移；工具名必须由受控 Profile 与 role-tool matrix 实际绑定，Prompt 不授予权限。

## When-to-use

同时满足以下条件时使用：

1. 已取得明确的 `incidentId`；
2. `get_threat_event` 返回 `status: OK`，能够识别事件、规则和核心实体。

本 skill 分两段：

- **立靶与建模段**：在工作流第 2 层取数后执行，把规则实际主张还原为可证伪断言，并生成具体场景。立靶失败时立即截断。
- **证伪与定论段**：各类证据到齐后执行，逐场景排除，再按安全定性类别归并。该段只消费已有结果，不重复调用取数工具。

没有 `incidentId` 时不使用。`get_threat_event` 返回 `ERROR` 时先记录接口失败并走主智能体的失败契约，不能把失败当成安全证据。

## Workflow

### 第一段：立靶与生成具体场景

#### 步骤 1 — 还原规则的实际主张

复用调度层已批量取得的 `get_rule_assertion(ruleIds[], layer)` 结果：

- 下游 `ruleId` 来自 `get_threat_event.producedByRuleId`；
- 上游 `ruleId[]` 来自 `get_threat_event.contributingAlerts[].ruleId`；
- 以 `condition` 和实际执行参数为准，不以规则名称、描述或 ATT&CK 标签代替规则逻辑。

重点读取：

| 字段 | 用途 |
|---|---|
| `condition` | 规则本次实际检测了什么 |
| `ruleType` / `groupField` | 检测和聚合粒度 |
| `windowSeconds` / `countThreshold` / `distinctCountField` | 时间窗、阈值与去重口径 |
| `layer` | 在检测链中的位置 |

规则体为 `EMPTY` 或 `ERROR` 时，可以从事件结构和关联告警共同特征做兜底反推，但必须标注来源及不确定性。下游主张既无法取得也无法反推时，输出 `verdict=UNDETERMINED`、`verdict_confidence=null`、`response_context=null`，记录缺失的规则体和补证方法，不继续取证。

上游规则体缺失不自动中止：只要下游主张可立住，就继续并把上游缺口记入 `data_gaps`。不得用告警自带的 ATT&CK 标签反推产生该告警的规则主张。

#### 步骤 2 — 把主张改写为可证伪命题

使用如下形式：

> 在 `<groupField>` 上、`<windowSeconds>` 秒内，实际事件满足 `<condition 的可执行语义>`；该事实可能由以下具体场景之一造成。

命题必须具体到可以列出必要条件，并能被带 ID 的矛盾证据排除。写不具体等同于立靶失败。

#### 步骤 3 — 在 H1-H4 下生成具体场景

H1-H4 只用于组织候选，不能把每类当成一个不可分割的假设：

| 类别 | 应生成的具体场景示例 | 安全定性类别 |
|---|---|---|
| H1 攻击或恶意行为 | 外部探测、失败利用、内部人员滥用、供应链投毒、失陷账号横向、恶意脚本执行 | 攻击/恶意 |
| H2 合法运维 | 已授权扫描器、计划任务、批处理、配置管理工具或人工运维 | 非攻击 |
| H3 非攻击性业务或系统行为 | 业务批任务、系统异常、配置错误、服务重试、健康检查或人工误操作 | 非攻击 |
| H4 检测主张失真 | 字段语义错误、聚合错位、阈值失真、脏数据或解析错误使核心主张不成立 | 核心检测主张无效 |

每个具体场景至少写明：`scenario_id`、类别、可观察行为、必要条件、可排除它的证据和当前状态。不要预设四类各自只能有一个场景，也不要预设 H2/H3 一旦有证据就自动排除所有 H1 场景。场景集只覆盖本次有数据支点的合理解释，**不宣称穷尽**现实世界的全部可能故事。

### 第二段：逐场景证伪并归并结论

#### 步骤 4 — 只用矛盾证据排除具体场景

对每个场景逐一核验：

1. 证据是否与该场景的必要条件直接矛盾；
2. 证据是否有可追溯的 `alertId`、`logId`、`vulnId`、`assetId` 等引用；
3. 否定性查询是否为 `EMPTY`，且 `sourceHealth`、时间窗和字段覆盖都足以支持“确认不存在”；
4. 该证据排除的是一个具体路径，还是确实排除了同类别的所有剩余场景。

`ERROR`、采集断流、字段缺失和错误查询范围都只能形成 `data_gaps`。它们不能排除场景，也不能提高结论确定性。

以下推断明确禁止：

- “没有看到攻击成功”推出“没有攻击”；**恶意尝试即使失败**，也仍是安全事实，事件可以判真；
- 某条利用路径不可达，推出整个 H1 不成立；
- H2/H3 有支持证据，直接推出所有恶意场景都不成立；
- 一条同时兼容恶意与良性解释的证据，被当成区分证据。

#### 步骤 5 — 按安全定性类别归并存活场景

先把尚未排除的具体场景归并为两组：

- **恶意组**：H1 下仍存活的攻击或恶意行为场景；
- **非恶意/主张无效组**：H2、H3 下仍存活的非攻击场景，以及 H4 下仍存活的核心检测主张无效场景。

然后按组定 `verdict`：

| 存活结果 | 事件结论 |
|---|---|
| 只有恶意组存活，且至少一个恶意场景有直接证据支持 | `TRUE` |
| 恶意组已被逐场景排除，非恶意/主张无效组有直接证据支持 | `FALSE` |
| 两组均有场景存活 | `verdict=UNDETERMINED`、`verdict_confidence=null`、`response_context=null` |
| 没有足够证据支持任一组，或关键必要条件不可观测 | `verdict=UNDETERMINED`、`verdict_confidence=null`、`response_context=null` |

`FALSE` 需要“恶意场景已被证据排除 + 非恶意或检测主张无效场景得到直接支持”这两个条件；仅仅没找到恶意证据不足以判假。

#### 步骤 6 — 独立记录攻击进展

事件真假与攻击进展是两个维度。对 `TRUE` 事件填写：

| `response_context.attack.progressed` | 条件 |
|---|---|
| `SUCCEEDED` | 有直接结果证据表明目标状态已被攻击行为改变或攻击目标已达成 |
| `ATTEMPTED` | 恶意行为本身有直接证据，但结果明确失败或尚未观察到得手 |
| `UNKNOWN` | 能确认恶意行为，但现有数据无法判断是否得手 |

`FALSE` 与 `UNDETERMINED` 不得借用进展字段暗示攻击成立。攻击进展未知不等同于事件结论不确定。

#### 步骤 7 — 先判结论，再定等级

必须**先判结论，再定等级**，且**不设默认等级**：

- 取值域固定为 `TRUE: 确认/高/中`、`FALSE: 低`、`UNDETERMINED: null`；
- `TRUE` 的三个等级根据直接证据质量、必要条件覆盖、独立来源一致性和关键数据缺口选择；
- `FALSE` 在四级口径中固定为“低”，表示事件主张被否定，而不是低质量的任意猜测；
- 每个等级都要引用使其成立的证据和限制因素；不能仅凭“感觉较像”给等级；
- 数据缺失只能降低确定性，不能提高确定性。

#### 步骤 8 — 记录 data_gaps

每条缺口固定且仅写 `{missing, affects, capability, how_to_close}`：`missing` 说明缺什么，`affects` 说明影响哪个场景或结论，`capability` 说明对应哪项能力，`how_to_close` 说明补什么可以继续判定；四个字段均须非空，不接受 `remediation` 或其他别名。

## Verification

本次执行只有在以下条件全部满足时有效：

| # | 检查项 | 验证方式 |
|---|---|---|
| 1 | 靶来自实际 `condition` | 可逐项对照规则断言；规则名和标签未替代条件 |
| 2 | 候选是具体场景 | 每个候选都有 ID、必要条件、证伪条件和状态，不只写 H1/H2/H3/H4 |
| 3 | 排除均有矛盾证据 | 每个被排除场景都有可追溯证据 ID；`ERROR` 未作证据 |
| 4 | 失败攻击未被误判为非攻击 | 对已确认恶意但未得手的行为，`verdict=TRUE` 且进展为 `ATTEMPTED` 或 `UNKNOWN` |
| 5 | 跨类别冲突未被强判 | 恶意组与非恶意/主张无效组同时存活时，三项空值契约完全满足 |
| 6 | 置信度无默认值 | 结论先产生；每个非空等级均有证据归因，`UNDETERMINED` 为 `null` |
| 7 | 缺口可行动 | 每条 `data_gaps` 都说明影响和补证方法 |
| 8 | 所有结论都生成统一报告 | `TRUE`、`FALSE`、`UNDETERMINED` 均进入写回流程 |

如果“被排除场景”没有矛盾证据引用，说明执行的是印象判断而不是证伪，本 skill 的结果无效。

---

## ATT&CK 覆盖

本 skill 不绑定具体 ATT&CK technique。ATT&CK 仅由 `threat-analysis-kill-chain-reconstruction` 用来分类已经观察到的行为，不能作为固定顺序或攻击事实本身。
