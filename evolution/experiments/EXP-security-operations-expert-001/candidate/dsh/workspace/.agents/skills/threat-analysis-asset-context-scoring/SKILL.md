> 本 Skill 仅由容器内 DSH 装载。来源为旧 Runtime 资产的业务语义迁移；工具名必须由受控 Profile 与 role-tool matrix 实际绑定，Prompt 不授予权限。

## When-to-use

在立靶通过、具体场景已生成，且 `get_threat_event` 提供实体信息后使用。立靶已经截断时不使用。

本 skill 提供场景判据，不直接给事件下最终结论。资产语境用于生成或支持 H2 合法运维、H3 非攻击性业务或系统行为的具体场景；可达性用于核验依赖某条路径的场景必要条件。

## Workflow

### 步骤 1 — 复用事件时点的实体归一结果

读取层 2 已取得的 `resolve_entity(identifiers[], atTime)` 结果，不重复调用：

- `identifiers[]` 来自事件实体及关联告警中的源、目标标识；
- `atTime` 必须是事件发生时间，不是当前时间；
- `entityId` 是资产语境、可达性、基线和日志取证的共同键。

| 情形 | 处理 |
|---|---|
| `status: OK` 且 `ambiguous: false` | 使用该 `entityId` 继续 |
| `ambiguous: true` | 不猜选实体；相关场景判据记为不可判定并写入 `data_gaps` |
| `status: ERROR` | 所有依赖该归一结果的判据弃权并写入 `data_gaps` |

IP、主机名和 FQDN 可能是同一实体，IP 也会随时间重分配。未归一或使用当前时间归一历史事件，都会让证据挂错对象。

### 步骤 2 — 获取实体语境并生成候选场景

按调度层一次批量取得 `get_entity_context(entityIds[])`。重点读取：

| 字段 | 可支持的判断 |
|---|---|
| `purpose` / `bizSystems` | 生成业务机制、服务重试、系统异常等 H3 场景 |
| `expectedAccess.interactiveLogin` / `allowedAccounts` | 判断登录行为是否符合资产约束 |
| `installedAutomation[]` | 生成具体 H2 合法自动化来源 |
| `identities[].isAutomation` / `ownerSystem` / `owner` | 将账号与受管自动化系统关联 |
| `isCritical` | 提供影响面上下文，不用于决定事件真假 |

语境是场景构造材料，不是结论。发现某自动化工具或业务用途，只能支持对应具体场景；还需用发起者、执行记录、变更单或行为特征建立本次事件与该场景的直接联系。账号名称看起来像服务账号不算证据。

### 步骤 3 — 按具体场景核验可达性与可利用性

批量调用 `check_feasibility(pairs[], atTime)`。`pairs` 只包含仍存活场景明确依赖的源、目标和方向，不要把所有实体任意两两组合。

| 返回字段 | 用途 |
|---|---|
| `reachable` | 该场景所需网络路径在事件时点是否可通 |
| `reachEvidence` | ACL、路由、连接状态等证据引用 |
| `targetExposure[]` | 目标服务、端口和版本是否满足场景前提 |
| `vulns[]` | 已核实的匹配漏洞及 `vulnId` |
| `intel` | 源实体情报，仅作辅助事实 |

逐场景判定：

| 情形 | 处理 |
|---|---|
| `status: OK` 且 `reachable: false` | **只排除依赖该路径的具体场景**；不得直接判整个 H1 为假 |
| `reachable: true` 且有匹配暴露面/漏洞 | 支持依赖该前提的场景，但不单独证明攻击发生 |
| `reachable: true` 但 `vulns[]` 为空 | 不能推出没有漏洞，也不能推出利用不成立 |
| `status: ERROR`、字段缺失或归一歧义 | 该判据为 `UNKNOWN`，记录 `data_gaps` |

网络阻断能否排除场景还取决于场景主张：

- 若场景声称攻击者已经通过该连接进入目标，且健康数据证明事件全程不可达，该场景必要条件被否定；
- 若已经观察到恶意载荷、探测或利用请求，但连接被阻断，**失败利用仍可能是真实攻击**，事件可以为 `TRUE`、进展为 `ATTEMPTED`；
- 本地执行、不同入口、代理路径、已失陷节点等**其他恶意场景**不依赖这条源目标路径，必须分别验证。

### 步骤 4 — 区分“确认不存在”与“没有数据”

空漏洞数组、空情报数组或缺少拓扑记录，不等同于目标安全或路径不可达。只有接口明确表达“覆盖完整且确认不存在”，才能把缺失作为否定证据；否则该角度弃权并说明补证方法。

弃权只影响依赖该数据的场景和置信度依据，不应给全局设置机械的等级上限。最终等级由证伪引擎在事件结论确定后，结合所有关键必要条件覆盖情况统一判断。

### 步骤 5 — 形成结构化输出

输出至少包括：

- `entity_contexts`：按 `entityId` 组织的资产、身份和自动化事实；
- `scenario_feasibility`：每个 `scenario_id` 的路径、暴露面、漏洞条件及状态；
- `evidence_refs`：`assetId`、`vulnId` 或其他可追溯证据；
- `data_gaps`：歧义、缺失、错误及其影响和补证方法。

## Verification

本次执行只有在以下条件全部满足时有效：

| # | 检查项 | 验证方式 |
|---|---|---|
| 1 | 所有判断基于 `entityId` | IP、主机名只作为输入标识，没有直接充当历史实体键 |
| 2 | 归一使用事件时间 | `atTime` 可追溯到事件发生时间 |
| 3 | 歧义未被静默选择 | `ambiguous: true` 的相关判据均为未知并记录缺口 |
| 4 | 可达性约束具体场景 | `reachable: false` 只影响依赖该路径的 `scenario_id` |
| 5 | 失败尝试未被抹掉 | 已观察恶意请求但被阻断时，没有因此判为非攻击 |
| 6 | 空数组未被解释为确认不存在 | `vulns[]`、`intel` 等缺数均未充当否定证据 |
| 7 | H2/H3 有直接关联 | 合法运维或非攻击性业务/系统解释能追到资产事实与本次行为之间的关联证据 |
| 8 | 弃权已记账 | 每个 `UNKNOWN` 都进入 `data_gaps`，说明影响与补证方法 |

## ATT&CK 覆盖

可达性对依赖网络路径的具体场景通常更有区分力，如 `Initial Access`、`Lateral Movement`、`Command and Control`、`Exfiltration`。对纯本地行为或未知入口，不得套用网络路径结论。
