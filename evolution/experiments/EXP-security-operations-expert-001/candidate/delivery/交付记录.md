## 一、智能体需求定义（迁移草稿）

需求与验收事实源已按《网络安全运营五类场景_需求任务测试评估与验收标准 V0.2》摄入：

- 需求事实源：`agents/security-operations-expert/spec/requirements.md`，34 项 `REQ-001..034`，源文档编号 `REQ-SOC-*` 作为迁移映射逐条保留；
- 验收事实源：`agents/security-operations-expert/spec/acceptance.yaml`，39 项 `AC-001..039`（含 5 项 Q01 质量目标）；确认状态为**待交付负责人确认**。

旧四域编号（响应处置 `REQ-001..010`、巡检 `REQ-011..018`、故障排查 `REQ-019..028`、策略配置 `REQ-029..038`）是迁移来源说明，不再作为当前事实源；原始需求正文保存在迁移历史中。

DSH 迁移新增的技术硬门禁包括：仅在容器中装载、开发 Candidate 与受控 Runtime 平面隔离、正式快照只读、凭据仅由 Runtime 注入、角色工具权限衰减，以及进入 Candidate Verification 或正式评估前必须使用复核后的快照、新容器和新 Session。它们将在业务 AC 确认后建立 `CTRL → AC → Case` 映射。

## 二、用户场景与输入覆盖矩阵（待业务复核）

输入覆盖以三类待复核材料为输入来源：

- 200 条旧候选：`agents/security-operations-expert/eval/pending/cases.pending.jsonl`，Case ID 全部保留且无重复；
- 115 条 V0.2 设计样例：`agents/security-operations-expert/eval/pending/scenario-design.pending.jsonl`（`D-*`，覆盖响应处置、巡检、故障排查、策略配置、知识问答五类场景与七种输入变体）；
- 4 条用户补充输入：`agents/security-operations-expert/eval/pending/user-inputs.pending.jsonl`（`D-FLT-21`、`D-FLT-22` 覆盖版本服务业务访问不可达与主备防火墙切换后访问失败，复用 `REQ-014`／`AC-016`；`D-INS-21` 覆盖常规巡检发起，复用 `REQ-008`／`AC-009`；`D-POL-27` 覆盖点对点开通 TCP 端口，复用 `REQ-020`／`AC-023`）。

这些材料均为待领域复核输入，不构成正式 Eval Set；旧矩阵存在一格多需求、缩写 Case ID 和非规范输入变体等问题，正式矩阵须在 AC 绑定时从经复核 Case 元数据重新生成。

## 四、安全与控制边界

旧 Prompt、权限配置和 Hook 不能充当 DSH 强制控制。候选以 DSH native guard、角色 `toolFilter`、只读 managed 挂载、Runtime 审批、MCP 服务端权限及独立审计重建控制。生产 Release 不允许自修改；隔离 Authoring 当前 Session 可实时看到探索行为，但模型写入只形成待审 Candidate diff，不授予 Candidate Verification 或正式评估的激活、Baseline 冻结或 Release 晋升权。

## 六、自测与交付评估报告

### 已确认的实质失败

- 巡检历史 Workspace 测试存在 7 项失败。
- 故障排查历史 Manifest 契约存在 1 项失败，Live 检查有 3 项跳过。
- 策略配置历史跨域路由存在 2 项失败，Console 测试未执行。

### 材料缺口

- 响应处置没有正式 Trial，材料不能证明完整交付；这不是已确认的实质失败。
- 200 条 Case 缠绕 `synthetic_reviewed` 与待业务签字的矛盾状态。
- 全部 Case 缺少 `acceptance_id`，旧结果文件没有 Trial，且不符合当前 17 列契约。
- 威胁研判、知识检索和通用安全调查虽随 Harness 迁入，但没有独立交付评估；启用前必须补齐范围或在 Release 中禁用。
- 真实模型、真实 MCP、最终业务状态与审计链尚未执行 R3。

### 唯一结论

退回整改。机器结构检查或 Mock MCP 集成验证均不得改写此结论。
