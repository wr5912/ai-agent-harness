## 一、智能体需求定义（迁移草稿）

四个能力域的旧需求已完成稳定编号映射：响应处置 `REQ-001..010`、巡检 `REQ-011..018`、故障排查 `REQ-019..028`、策略配置 `REQ-029..038`。原始需求正文保存在迁移历史中。业务负责人尚未确认项目特有 `AC-xxx`、硬门禁阈值和需求到 AC 的关联，因此本文件不伪造正式 AC。

DSH 迁移新增的技术硬门禁包括：仅在容器中装载、开发 Candidate 与受控 Runtime 平面隔离、正式快照只读、凭据仅由 Runtime 注入、角色工具权限衰减，以及进入 Candidate Verification 或正式评估前必须使用复核后的快照、新容器和新 Session。它们将在业务 AC 明确后建立 `CTRL → AC → Case` 映射。

## 二、用户场景与输入覆盖矩阵（待业务复核）

200 条不同输入已迁移至 `eval/cases.pending.jsonl`，Case ID 全部保留且无重复。它们覆盖响应处置、巡检、故障排查和策略配置，但旧矩阵存在一格多需求、缩写 Case ID 和非规范输入变体矩阵等问题；正式矩阵须在 AC 绑定时从经复核 Case 元数据重新生成。

## 三、任务与评估数据集说明

当前文件是迁移候选，不是正式 Eval Set。所有 Case 的 `review_status` 和 `acceptance_mapping_status` 均为 `pending`；旧 `synthetic_reviewed` 声明仅作为 `migration.original_source_type` 保存，因为原材料同时标注 `technical_only_pending_domain_signoff`。本轮不生成 `cases.jsonl` 或 `results.csv`。

## 四、安全与控制边界

旧 Prompt、权限配置和 Hook 不能充当 DSH 强制控制。候选以 DSH native guard、角色 `toolFilter`、只读 managed 挂载、Runtime 审批、MCP 服务端权限及独立审计重建控制。生产 Release 不允许自修改；隔离 Authoring 当前 Session 可实时看到探索行为，但模型写入只形成待审 Candidate diff，不授予 Candidate Verification 或正式评估的激活、Baseline 冻结或 Release 晋升权。

## 五、候选基线状态

当前尚未冻结 `bl-<UUIDv4>`。DSH Commit、镜像、Profile、Preset、插件、MCP roster/schema、模型、控制、Eval Set、评估器和环境尚未形成完整冻结组合。不得把本 Experiment、旧 Commit 或空结果表称为候选基线。

## 六、自测与交付评估报告

### 已确认的实质失败

- 巡检历史 Workspace 测试存在 7 项失败。
- 故障排查历史 Manifest 契约存在 1 项失败，Live 检查有 3 项跳过。
- 策略配置历史跨域路由存在 2 项失败，Console 测试未执行。

### 材料缺口

- 响应处置没有正式 Trial，材料不能证明完整交付；这不是已确认的实质失败。
- 200 条 Case 缠绕 `synthetic_reviewed` 与待业务签字的矛盾状态。
- 全部 Case 缺少 `acceptance_id`，旧结果文件没有 Trial，且不符合当前 17 列契约。
- 威胁研判、知识检索和通用安全调查虽随 Harness 迁入，但没有独立交付评估；启用前必须补齐范围或在 Release 中禁用。
- 真实模型、真实 MCP、最终业务状态与审计链尚未执行 R3。

### 唯一结论

退回整改。机器结构检查或 Mock MCP 集成验证均不得改写此结论。
