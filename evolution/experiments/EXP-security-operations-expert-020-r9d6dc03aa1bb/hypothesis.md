# EXP020：威胁研判固定流程接入网页 MCP 配置

直接主来源为 `EXP-security-operations-expert-019-rc442472a242a`，固定于 Git `0ae67c84fb6f53a04a99f33ac25561d067684504`；Baseline 同为该提交。Candidate 完整继承新版 EXP019 的摘要配置入口、MCP 工具与资源分组、语音、巡检、故障取证、自动威胁研判及其余既有能力，并同步主分支当前术语，不复制来源 Experiment 的 Run、Evaluation 或 Decision。

本地未提交工作树 `EXP-security-operations-expert-019-rff6fbace27a0` 仅作为研究意图的迁移来源。它尚未实现 MCP 接入，Candidate 除身份外仍等同 EXP018；因此本实验只保留其中“让威胁研判固定流程使用网页 MCP 配置管理中的 SOC 与报告连接”的研究问题和验证范围，不迁移旧 Candidate、依赖安装目录或缓存。MCP 工具、资源和资源模板分组以新版 EXP019 的实现为准。

本轮选择保持 `analyze_threat_incident` 为模型侧唯一复合工具，不改变 Guard、Skill、子智能体工具范围和自动 Schedule 语义。网页中的 SOC 与报告服务器及 `threat-analysis-runtime` 分组作为上游连接、凭据和能力范围的唯一运行事实源；插件从本实例实际 Web 端口派生回环分组地址，启动环境只注入分组共享 Token。每次手工研判或待研判读取建立一个运行级 MCP Client，动态发现并固定映射分组内的 Tool、Resource 与 Resource Template，再通过带随机临时密钥的本机桥供现有 Python 固定流程调用。Python 不接触网页共享 Token，也不再读取旧资源网关地址、报告地址或静态资源 UUID 目录。

研究假设是：这条连接迁移可以保留事件认领、分页取证、五源融合、结果校验、SOC 成功或失败回写、报告存储以及受信 Schedule 语义，同时不向模型开放底层写工具。为可靠保留认领冲突，OpenAPI Tool 返回的真实 HTTP 状态进入 MCP 标准 `_meta`，固定桥只读该结构化字段，不从错误正文猜测 409。分组工具发现按成员隔离失败，使报告服务不可用时仍能验证并执行必需 SOC 能力；报告保存继续保持非阻断。

## 预期观察

- 新 Candidate 能以新版 EXP019 的 MCP 工具与资源分组能力启动，已有业务路由和复合研判边界不回退。
- 网页配置的 SOC 与报告服务器及 `threat-analysis-runtime` 分组能够被新实例发现；缺少固定流程所需能力时在事件认领前明确失败。
- OpenAPI 认领接口返回 409 时，MCP 结构化状态能够传递到自动研判的 `skipped_locked` 分支。
- 完成接入后，一条手工威胁事件能够走完认领、取证、研判、SOC 结果或失败回写及报告保存。
- 一次受信 Schedule 心跳仍只处理一条事件，并保留忙碌、旧心跳和认领冲突处理。
- 结构化材料回答、巡检续查和只读故障取证的必要回归没有因连接迁移而失效。

## 停止条件

- 网页 MCP 配置无法成为固定研判流程的连接来源，且只能重新维护一套等价的上游地址与凭据。
- 接入要求放弃现有失败回写、幂等、事件级互斥或自动 Schedule 边界。
- 需要把 LLM API Key、MCP Token 或其他凭据写入普通研究证据。

当前仍需用真实事件验证 OpenAPI 适配器的单次 20 秒和 1 MiB 响应限制是否会影响 `search_event` 等慢查询或大结果；没有实际触发前不提前扩展缓存、超时或大结果协议。

## 验证范围

本实验先覆盖 PA-03、PA-04 的 Experiment 与来源合同；实际启动和装载后覆盖 PA-05、PA-06、PA-07。只有执行真实手工事件、Schedule 心跳及必要回归后，才能形成 PA-08 范围内的业务观察。静态校验、网页发现工具或容器启动不代表威胁研判闭环成立。
