- 观察到的缺口：场景中「核对设备映射、型号能力、ACL 模板/设备可配置能力」这一族要求在角色工具矩阵与只读取证子 Agent 的工具清单中不存在对应工具：全部相关 Case 的工具证据里没有任何设备型号能力、ACL/模板或策略设备枚举调用。模型因此在 U-POL-002/004/010 被判 failed，但 U-POL-001/003/006 同样未做此核对却未被同等扣分。
- 根因假设：场景预期隐含了当前 sec-ops 合同未提供的设备能力查询接口（role-tool-matrix/agent 指令只列出资产、拓扑、覆盖、事件类只读工具与三个策略准备工具），使「设备能力校验」在任何实现下都无法完成，评测却把该缺口记作被测行为失败。

- 反例 Case：U-POL-001, U-POL-006
- 替代解释：被测模型本可主动声明「设备能力查询能力不存在」并停在缺口上（U-POL-010 的回复正是如此），失败可能只是模型未按 skill 要求识别缺口，而非工具缺失。

#### 策略配置 · evaluation_method

- 观察到的缺口：同一「设备适用性核对」要求在不同 Case 中计分不一致：U-POL-001（输入含「防火墙虚拟机」，但工具与回复均未解析执行设备、target_external_id 为 null）判 passed，U-POL-006（同样只做 prepare/result、无资产与路径核对）判 passed，而 U-POL-002/004 因缺少设备核对判 failed，且评分理由未说明区分标准。

#### 策略配置 · harness_mechanism
