# 研究假设

同时约束巡检子 Agent 的最终正文和主 Agent 的转交方式，可消除同一结果被二次改写造成的重复与内部字段外露，使“执行一次常规巡检”优先呈现真实报告入口、结论、关键结果和建议，同时保持工具事实、未知项与执行状态准确。

本实验只调整用户可见输出合同，不改变 `start → collect → finalize` 执行链、MCP 工具集合、角色隔离或 Guard。以全新 DSH Web Session 的回答和对应执行轨迹共同判断结果。

## 预期观察

- 主 Agent、巡检子 Agent、故障分析和响应规划的工具数量及隔离关系与 Baseline 一致。
- 常规全量巡检仍按顺序完成 `start`、`collect`、`finalize`，后两步复用同一 `run_id`。
- 最终回答首行概括状态或最重要结论；工具返回真实报告 URL 时，链接原样保留并紧接标题、位于摘要之前。
- 正文依次呈现简短结论、关键结果、建议和巡检概况；必要事实写入对应结果，不另设内部证据板块；工具未声明集合关系时，各数值分别陈述，不自行计算或解释汇总值。
- 默认不展示 `run_id`、`report_id`、`result_digest`、工具调用链或委派元数据；回答中的状态、数量和链接与本次工具结果一致。

## 停止条件

- 调整导致报告链接、失败状态、未知项或关键工具事实丢失，或产生工具未支持的数值关系；
- 巡检执行链或角色工具隔离发生回归；
- 验证会触发策略变更、计划任务或响应处置。
