直接来源为 [EXP-security-operations-expert-017-r94f3b07e080f](../EXP-security-operations-expert-017-r94f3b07e080f/hypothesis.md)，固定于 Git `5e1447d14a9c202aae05144034100a1ce685dee0`；Baseline 为 `git:5e1447d14a9c202aae05144034100a1ce685dee0`。沿用该来源已融合的语音、Web/MCP、三工具巡检、周期巡检、自动研判、只读故障委派和 OpenAPI 能力。其四个并行来源及历史取舍见来源研究假设，本次未新增并行能力，也未采纳旧 Skill 或探索性 010 Variant。创建前已核对远端三个分支、单一工作树及当前同 Agent 来源。

同来源两次 API Run 中，`U-INS-003` 一次返回 Markdown 围栏和输入外时间字段，并尝试无授权写文件；另一次返回裸 JSON。当前指令同时默认 Markdown 和笼统要求可解析 JSON，未说明全文解析及写文件条件。第一次 Candidate 修订明确格式优先、全文单 JSON 和写入条件，但重复 Run 仍发生被 Guard 拒绝的响应规划委派及主 Agent 输出围栏；没有实际启动子智能体，不能把失败归因于子智能体输出。

最终 Candidate 只修改工作区 `AGENTS.md`：将已有材料整理明确为主 Agent 直接回答的路由，区分材料中的业务词与执行请求；先确定用户格式，只有未指定格式时才用 Markdown；保留事实与单位，不补造时间、状态等字段，不作无基准数量判断，提示标注尚未执行。`harness.yaml` 仅登记新 Experiment 身份和固定 Baseline，其他资产逐文件继承。具体迭代与失败见[观察](evaluation/observations.md)。

使用同一标准镜像和 `local-qwen / Qwen3.8-27B`、不变 Case，在新实例与新 Session 重跑 `U-INS-003`、`U-INS-007`、`U-QA-012`、`U-QA-013`，并覆盖目录只查、周期参数追问、故障只读权限和英文输出四项回归。保留所有失败 Run；直接解析完整回答，由开发会话复核事实、单位及未执行建议，不从同模型自评推断业务通过，也不把开发会话复核称作独立人类采纳。每次语义修订后重新比较受影响 Case；两次重复只支持本模型与本输入的观察，不表示普遍稳定性。

停止条件：JSON 仍无法解析或事实失真时继续研究；巡检 `PARTIAL`、外部接口不足或评审器非 JSON 单独记为证据限制，不降低 Case。记录证据定位成本与两个隔离实例的身份、实际装载、状态和时间；它们属于工具验证，不替代业务或平台验收。
