# 摘要播报延迟优化

Baseline：`git:8416a373f89ffeec4b611f5a1419513b41cee5bb`；直接来源：`EXP-security-operations-expert-019-rc442472a242a`。完整继承其 Candidate，保留摘要设置入口、MCP 工具/资源/模板范围、全部业务 Preset 与 Guard，不按编号推断或重建能力。远端 main 已含此前来源；本地旧 main 保留在原工作树。

研究假设：只在语音摘要辅助调用中按模型公开能力关闭思考、限制输出及等待，并消除远程 TTS 与浏览器的整句缓存，能够减少正常 Call 完成后的摘要及首次播报等待。主调用有效模型设置与业务行为不变。

修改范围：摘要生成及其调用方、远程 TTS/队列、音频协议与客户端、当前 Qwen 能力声明、对应测试与构建制品。复用锁定 Runtime 标准镜像；不修改 Runtime 源码，不新增全局推理策略。

比较口径：Agent evaluation.md 的 U-VOICE-002/003 及新增延迟用例；受控外部接口与真实模型/听感分开记录。默认 30 字，两个模型分别观察否定、风险、未完成状态的三类输入各三次；目标热态摘要中位数不超过 2 秒、首次播报不超过 3 秒，原长等待中位数减少至少 50%，正常样本无漏播或语义失真。模型凭据或服务缺失时保留限制，不以受控结果声明真实性能达标。

停止条件：关闭参数无法通过当前适配器表达、主调用行为变化、发生漏播或迟到重播时，先修正对应合同；证据不足时 Decision 为 continue 或 inconclusive。
