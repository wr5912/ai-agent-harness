# 研究假设

把可调用工具收敛到实时 MCP 目录中存在的精确名称，并由角色矩阵统一约束 Profile 与 Guard，可使网络安全运营专家在新会话中只使用已验证路线；不可用能力会被明确报告，而不会猜测工具名或绕过路由。

## 预期观察

- 静态合同能证明角色矩阵、Profile 和 Guard 的允许集合一致，所有 MCP 工具名不超过运行时上限。
- 实时目录能找到全部允许工具；威胁分析、知识库检索、巡检执行和策略决策不再作为可用路线。
- 新 DSH Web Session 能选中本 Experiment 的 Preset，并对代表性输入使用正确工具或明确说明能力边界。
- 既有零工具响应规划的输入、输出和 Gate 行为保持不变。

## 比较方式

Baseline 使用 `git:fe472a1fefa49be4a59ee5364eaa43c5538805e6`。Candidate 只比较工具合同、路由选择、运行时装载和用户可见行为，不复用旧 Experiment 的运行记录作为当前证据。

## 停止条件

- 实时 MCP 目录不再包含任一允许工具；
- Profile、Guard 与角色矩阵无法保持精确一致；
- 新容器或新 Session 未实际加载 Candidate；
- 验证需要调用策略选择/决策、巡检执行或其他有业务副作用的工具。
