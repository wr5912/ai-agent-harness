# 研究假设

历史 EXP-010 的巡检 Run 在 `U-INS-001` 暴露了工具未注册和真实业务链未完成的问题。当前巡检 Skill 已约束单次启动、同一 `runId` 续查和报告链接来源，但没有明确要求处理服务未返回设备数量的情形；`evaluation.md` 要求该字段缺失时不得判通过。本次仅补这一条答复规则，测试它能否让模型如实报告缺口，同时保留目录查询和续查行为。

Baseline 为本分支起点提交 `97236e16ebca8e49623959ec9afdfe77002bbdb9` 中的 EXP-009 Candidate；本实验的 Candidate 从该目录复制，业务变更只有 `security-inspection/SKILL.md` 的设备数量规则。使用同一份 `evaluation.md` 的 `U-INS-001`，以 `U-INS-002` 和 `U-INS-007` 查回归。两边均需新实例和新 Session，固定标准镜像、模型、巡检 MCP 和 Case 口径，分别封存 Run、原始回答与工具调用，再比较。至少重复一次，分别记录手工流程和最小 CLI 的操作步骤、耗时、错误与人工核对量。

若巡检服务、工具注册或模型凭据不可用，保留失败或未知状态，不把静态检查、旧 Run 或本地替身当作业务效果证据。本轮 Decision 先由 AI 按原始记录作临时判断；真实业务采纳仍需研究者亲自核对原始记录。
