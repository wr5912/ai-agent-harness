# 研究假设

以 EXP-016-r77d4eb1119fb 的 Candidate（`git:c72506dee5d91b396da30c6c267a4ec11d226ae3`）为主来源，保留它继承的 EXP-015-r904bdcd81005 Web MCP 四连接、巡检三工具与容错报告解析，以及 EXP-016 的语音摘要、语音输入和手动朗读。融合并行的 EXP-015-rbe8b91182ebf（`git:c0f067e9752cef78fc6b20c6fd33c9df1e2a4dc5`）自动威胁研判：保留受信 Schedule 桥、待研判队列、一次一条的认领与研判、冲突跳过、超时失败回写和 Qwen JSON 围栏解析；其较早的语音制品由 EXP-016 版本替代。该并行来源仍是 active Experiment，合入其能力不表示已完成业务验收。

另一并行来源 EXP-015-r6328dfd1ae6e 已固定为 `git:150a127a29de02f504407127d1f4aef4018b0277`；按该提交重新核对巡检三工具和目录/结果经验。Web MCP 种子冲突时保留 EXP-016 的直连配置及本实验后续验证的 SOC 只读取证配置；旧 OpenAPI/login 种子和旧环境变量注册由此替代。

补充并行来源 EXP-017-rb20b8c6b906f（`git:96558afd1a8a3830bf444cf5db7d2b80e2e2b22d`）的 OpenAPI 修复：恢复规范匿名读取、仅在 401/403 后按已有授权重试、DSH Schema 子集转换及页面说明，源码与生成制品一起核对。其旧语音版本由 EXP-016 摘要版本替代；自动研判沿用 EXP-015-rbe，周期巡检、故障证据约束、Qwen 默认模型与 `/v1` 地址、Agent MCP 本地挂载授权沿用本实验已有实现。业务调用继续按原授权执行，业务 403 不回退为匿名调用。

OpenAPI 比较使用已有回归用例同时加载来源与本实验的实际生成制品，再在本实验实例中核对 Web 发现、资源读取、DSH Schema 和页面操作。文件差异检查仅定位待审查内容；来源齐全和文件无缺失都不能代替行为证据，剩余历史语义及业务路径仍按 Evaluation 判断。

在上述 Candidate 上复用锁定 DSH Runtime 已安装的自动化任务插件，并让根 Agent 看见 `schedule_create`。若用户明确授权每 10 分钟巡检当前全部资产，智能体应先核对设备在线状态模板对“当前资产清单”的描述，创建绑定当前 Session 的周期提醒；每次实际到期时，以原授权为依据重新查询目录，只发起一次巡检，并沿用该次 `runId` 查询结果和范围。

比较 `U-INS-004/005` 的新 Session 工具轨迹与服务回执。`schedule_create` 成功只证明提醒创建；必须观察一次真实到期消息、随后发起的巡检及结果查询，才能判断周期执行成立。若服务不能证明模板覆盖当前全部资产，或提醒只被展示而未触发工具链，则保持 `continue` 并记录原因。
