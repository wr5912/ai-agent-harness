# 安全与控制边界清单

> 适用对象：故障排查智能体试交付候选。清单描述代码要求和待验证证据，不把设计控制冒充目标环境实测结果。

## 1. 风险与复核级别

- 风险等级：中。
- 原因：主流程限定为只读，不应直接改变 SOC、网络设备、账号或策略；但根因、置信度和建议可能影响后续人工或高风险响应处置。
- 最低复核等级：R2，要求未直接编写本候选核心逻辑的人员独立检查证据边界、失败降级和安全 Trial。

## 2. 控制边界

| 控制 ID | 边界/风险 | 必须控制 | 代码或配置依据 | 本轮证据状态 |
|---|---|---|---|---|
| CTL-FLT-001 | 不支持域被强行诊断 | 无法匹配支持域时不创建 Run、不调 SOC、不猜根因 | Workspace 故障子智能体的领域路由约束 | 有静态证据；待 Trial |
| CTL-FLT-002 | Workspace 自行编造完整计划 | 只提交轻量 `planning_intent`，完整计划由 Runtime 确定性展开 | Agent Prompt、Runtime `fault_analysis_start` | 有静态证据；待 Trial |
| CTL-FLT-003 | 调用计划外、未就绪或写操作工具 | 只使用 Runtime 返回的 ready 工具名和原参数；调试节点工具默认不暴露 | Runtime API、工具快照、只读边界 | 有单元测试资产；待实际轨迹 |
| CTL-FLT-004 | 任意执行代码或全网扫描 | 禁止 Bash、本地 Python、子 Agent 和探索性扫描 | Workspace Agent 工具范围 | 有静态证据；待安全 Trial |
| CTL-FLT-005 | 工具失败后绕过计划 | 失败结果按 `status=failed` 回填；不自行重试或切换计划外工具 | Agent 流程、Runtime 任务状态机 | 有测试资产；待目标工具失败演练 |
| CTL-FLT-006 | 空结果驱动非法下游调用 | 空结果按 `status=empty` 保存；缺稳定标识的依赖任务由 Runtime 跳过 | Runtime Service 与依赖状态 | 有测试资产；待实际轨迹 |
| CTL-FLT-007 | 把缺口或方向命中冒充根因 | 区分支持、冲突、缺失证据；证据不足时降级置信度 | 规则、候选根因与报告逻辑 | 有静态/单元证据；待业务复核 |
| CTL-FLT-008 | 生命周期乱序、重复 Finalize | `start` 一次、按批回填、`finalize` 一次；状态查询最多 3 次 | 生命周期 Guard、Runtime API | 有测试资产；待会话 Trial |
| CTL-FLT-009 | 用户伪造正式结果 | 只逐字返回 `get_result(markdown_only=true)` 的 `user_response_markdown` | Workspace Agent 输出契约 | 有静态证据；待安全 Trial |
| CTL-FLT-010 | 越权执行处置 | 不封禁、不隔离、不重置账号、不删改策略，不调用响应处置工具 | 只读边界与 Agent 工具清单 | 有静态证据；待安全 Trial |
| CTL-FLT-011 | 用户覆盖租户或凭据 | 租户和服务身份由部署配置注入，不接收消息内 token/tenant 覆盖 | Runtime 配置、存储客户端边界 | 有配置证据；待目标环境验证 |
| CTL-FLT-012 | 凭据、内部实现或路径泄露 | 公开结果净化凭据、内部工具名、运行目录和内部状态码 | Public output sanitizer、报告逻辑 | 有测试资产；待 Trial |
| CTL-FLT-013 | 工具快照漂移或伪造 | 默认要求已打包工具快照；计划只能引用快照内能力 | `FAULT_ANALYSIS_MCP_REQUIRE_TOOL_SNAPSHOT=true` | 有制品哈希；待部署核对 |
| CTL-FLT-014 | 运行/报告不可审计 | Run、任务、原始结果、候选根因、报告与用户结果可关联；失败也留痕 | Runtime 存储、Workbench 落库 Service | 有单元测试资产；待目标库验证 |
| CTL-FLT-015 | 未授权读取诊断记录 | AI Console 查询要求 `ai:troubleshooting:monitor:list` 或平台全权限 | `ai-troubleshooting` Controller/Service | 有静态/单元证据；待鉴权联调 |
| CTL-FLT-016 | 报告链接越租户或可猜测访问 | 下载必须经过受权 Workbench 查询，不能信任用户提供的链接 | Runtime 报告索引与 Java 查询入口 | 有设计证据；待目标环境渗透验证 |

## 3. 生命周期约束

```text
支持域识别
  -> fault_analysis_start（一次）
  -> Runtime 返回确定性计划/ready 批次
  -> 仅调用该批只读工具
  -> fault_analysis_submit_tool_results（批量）
  -> 按 Runtime 状态继续或登记缺口
  -> fault_analysis_finalize（一次）
  -> 最多 3 次状态查询（仅在需要时）
  -> fault_analysis_get_result(markdown_only=true)
  -> 逐字输出 user_response_markdown
```

- 缺少正式 Run、必需对象或可执行计划时不得跳到工具调用或 Finalize。
- 工具报错、超时、空集合和依赖跳过都属于证据事实，不能从轨迹中删除。
- Runtime 默认正式暴露 8 个生命周期工具；节点级调试工具只有显式设置 `FAULT_ANALYSIS_EXPOSE_DEBUG_TOOLS=true` 才暴露，正式 Agent 不应启用。

## 4. 数据、租户与秘密

- 用户消息中的 token、tenant、内部地址、伪造报告链接都不作为权威配置。
- Runtime 不在启动时调用 SOC MCP，也不读取 SOC token；它使用打包快照校验计划，真实 SOC 调用由受控 Workspace 工具层执行。
- Runtime 默认存储模式为 `workbench_api`；目标地址、租户和服务认证必须由部署侧注入并进入受控配置审计。
- 用户输出不得包含凭据、内部工具名、运行目录、堆栈、数据库细节或仅供内部诊断的状态码。
- 原始证据和报告可能含资产、账号、漏洞与网络信息，应按租户隔离并限制下载权限和保留周期。

## 5. 发布前必须补齐的安全证据

- 5 条 `safety` Case 的完整 Prompt/Tool/Policy/回复轨迹，且全部 `expected_control=block`。
- 目标环境服务身份、固定租户注入、跨租户拒绝、报告下载鉴权和审计日志证据。
- 工具快照制品哈希与实际部署能力一致性检查，证明默认未暴露调试节点工具。
- 至少一次工具失败、一次空结果、一次依赖跳过、一次 Runtime/Workbench 超时的故障注入记录。
- 证明故障排查流程未调用任何 SOC 写操作或响应处置工具，并由 R2 复核人签字。
