# 智能体需求定义

> 文档状态：试交付评审稿。本文描述 `main@d74cf6387a2e816637dd2efe2eb2a38deb6b8816` 的故障排查能力，不代表正式 Eval Trial 或发布验收已经通过。

## 1. 基本信息

- Agent 名称：网络安全故障排查智能体（Network Security Fault Analysis Agent）
- 需求版本：`fault-diagnosis-requirements-trial-v0.1`
- 交付负责人：待团队指定
- 开发成员：周洋（材料发起人，身份待本人确认）；Codex（材料整理）
- 发布执行人：本轮不发布
- 风险等级：中（主链只读取证，但诊断结论可能影响后续人工或响应处置决策）；最低复核等级 R2

## 2. 用户与问题

- 主要用户：SOC 安全运营人员、网络与安全设备运维人员、事件与故障分析人员。
- 典型问题：业务访问异常、资产运行状态异常、资产关联异常、漏洞暴露风险、主机安全配置风险、检测/告警链路异常、级联数据同步异常、身份认证与登录异常。
- 当前实现：Workspace 子智能体只生成轻量 `planning_intent` 并驱动会话；Runtime MCP 根据内置领域、规则和工具快照确定性生成只读计划，接收证据、形成候选根因和报告；Workbench 保存运行记录并向 AI Console 提供受权查询。
- 主要风险：把领域匹配误当根因、在证据缺失时猜测、调用计划外或写操作工具、生命周期乱序、跨租户查询，以及把内部工具、路径、凭据或伪造报告暴露给用户。

## 3. 目标任务与成功标准

| 需求 ID | 目标任务 | 可验证的成功标准 | 优先级 |
|---|---|---|---|
| REQ-FLT-001 | 识别受支持故障域与分析方向 | 对八个支持域生成唯一 `domain_id` 和适用方向；无法匹配时不创建正式 Run、不调用 SOC 工具、不猜根因 | P0 |
| REQ-FLT-002 | 创建轻量意图并由 Runtime 确定性规划 | Workspace 不展开完整查询计划；`fault_analysis_start` 只调用一次；对象或必需字段缺失时返回不可执行计划 | P0 |
| REQ-FLT-003 | 只调用计划内、当前就绪的只读工具 | 严格使用 Runtime 返回的工具名与参数；同一批可并行；禁止 Bash、本地 Python、探索性查询和写操作 | P0 |
| REQ-FLT-004 | 批量回填并保留证据谱系 | 将成功、失败、空结果按契约批量提交；保留原始结果和任务标识；不伪造、不丢弃异常证据 | P0 |
| REQ-FLT-005 | 安全处理缺信息、失败、空结果和依赖跳过 | 不用空 ID 或占位符调用下游工具；不重试或换计划外工具绕过；把缺口记为缺口而非反证或根因 | P0 |
| REQ-FLT-006 | 基于证据生成候选根因与置信度 | 规则和证据共同支持候选；区分支持、冲突和缺失证据；领域或方向命中本身不等于根因成立 | P0 |
| REQ-FLT-007 | 按生命周期收口并返回正式结果 | 证据完成或缺口登记后只 `finalize` 一次；必要时有限查询状态；最终逐字返回 Runtime 的 `user_response_markdown` | P0 |
| REQ-FLT-008 | 保存可审计记录和报告 | Run、计划、工具结果、证据、候选根因、报告与用户结果可关联；监控接口按权限只读查询 | P1 |
| REQ-FLT-009 | 守住只读、租户与数据安全边界 | 不执行封禁、重置、删除等处置；租户和凭据不接受用户消息覆盖；敏感信息不进入公开输出 | P0 |
| REQ-FLT-010 | 抵御注入、乱序和结果伪造 | 拒绝绕过 `start`/取证/`finalize` 的请求；不接受用户伪造的正式结果或报告链接；不扩大工具权限 | P0 |

## 4. 输入与输出

- 输入：用户自然语言故障描述；资产、账号、节点、源/目的地址、端口、时间窗等已知对象信息；Runtime 返回的计划状态和工具任务。
- 必需上下文：支持领域与方向定义、只读工具快照、规则与证据映射、固定租户、运行状态、已回填原始证据和依赖关系。
- 中间动作：生成轻量规划意图；启动一个 Run；按 ready 批次调用指定只读 SOC 工具；批量提交原始结果；按 Runtime 指示继续或收口。
- 输出：Runtime 生成的用户可读诊断 Markdown、候选根因与置信度、证据缺口、报告信息和可审计 Run 标识。
- 监控查询入口（由 `ai-bff` 统一前缀组装）：故障诊断列表、目录、Run 详情和报告下载查询。

## 5. 非目标

- 不执行封禁、隔离、重置账号、删除策略、修改配置、创建工单或其他响应处置动作。
- 不运行 Bash、本地 Python、全网扫描或任意探索工具。
- 不把故障域、方向、告警名称或资产标签直接当成已确认根因。
- 不在对象、时间窗、稳定标识或关键证据缺失时编造参数、证据、置信度或报告。
- 不替代响应处置智能体、巡检智能体或威胁分析智能体；本交付包与这些智能体分别评估。
- 本轮不发布，不修改业务代码，不执行 50 条真实会话 Trial。

## 6. 依赖与约束

- Workspace 入口：`ai/security-operations-expert/workspace/.claude/agents/network-security-fault-analysis-expert.md`。
- Runtime：`ai/fault-diagnosis/runtime-mcp`，正式暴露 8 个生命周期工具；调试节点工具默认关闭。
- 证据工具：以 Runtime 打包的 MCP 工具快照和确定性计划为准；快照记录 56 个可发现工具，不代表智能体可任意调用。
- Workbench：`ai/ai-workbench/ai-troubleshooting` 保存 Runtime 写入的记录，并提供受权只读监控查询。
- 存储：Runtime 默认使用 `workbench_api`，需要部署侧注入 Workbench 地址和租户；最终写入超时默认 180000 毫秒。
- 状态约束：每轮只处理 Runtime 标记为 ready 的批次；依赖未满足由 Runtime 跳过；状态查询最多 3 次；结果必须取自 `get_result(markdown_only=true)`。

## 7. 已知风险与限制

- 具体模型、采样参数、目标 AgentGov/MCP/Workbench 制品、目标环境租户与认证配置尚未冻结，当前 Baseline 不能复现完整真实链路。
- 50 条 Case 是按当前代码、八域定义和证据契约构造的技术候选集，尚未由各领域业务人员逐条签字，也未执行正式 Trial。
- 本地单元测试只能验证 Runtime、Workspace Policy 和 Java 查询/落库契约，不能单独证明目标环境中的工具可用性、租户隔离、报告访问控制和诊断准确率。
- 故障结论可能推动高风险处置；使用方必须把候选根因、置信度和证据缺口完整传递给人工或响应处置流程，不能只截取结论。
