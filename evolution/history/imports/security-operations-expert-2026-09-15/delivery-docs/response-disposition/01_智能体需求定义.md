# 智能体需求定义

> 文档状态：试交付评审稿。本文描述 `main@d74cf6387a2e816637dd2efe2eb2a38deb6b8816` 的响应处置能力，不代表正式 Eval Trial 或发布验收已经通过。

## 1. 基本信息

- Agent 名称：响应处置智能体（Response Disposition Agent）
- 需求版本：`response-disposition-requirements-trial-v0.1`
- 交付负责人：待团队指定
- 开发成员：周洋（材料发起人，身份待本人确认）；Codex（材料整理）
- 发布执行人：`N/A`，本轮不发布
- 风险等级：高（流程最终可触发 SOC 真实处置写操作）；最低复核等级 R3

## 2. 用户与问题

- 主要用户：SOC 安全运营人员、事件响应人员，以及向 Workbench 投递受信研判结果的授权系统。
- 典型触发场景：根据威胁分析或已登记故障分析结果生成处置方案；在已发布剧本中选择；用已冻结原子动作生成临时候选；完整查看后批准、拒绝或要求修订；监控执行并验证业务效果。
- 当前处理方式：Java `ai-response` 负责来源校验、事实冻结、候选编译、确认绑定、SOC strict manual 提交、持久化监控和效果评估；Workspace 规划 Skill 只在严格门禁下对冻结候选做最多一次语义消歧，保持零副作用。
- 主要问题：真实处置有高风险副作用，必须保证来源、目标、动作、参数、候选版本、人工确认和最终提交一一绑定，并在超时、崩溃和结果未知时避免重复执行。

## 3. 目标任务与成功标准

| 需求 ID | 目标任务 | 可验证的成功标准 | 优先级 |
|---|---|---|---|
| REQ-RSP-001 | 接入受信来源结果 | 请求方认证通过；按结果 ID 查询并校验 Schema、版本和摘要；重复投递幂等；入口不直接执行 SOC | P0 |
| REQ-RSP-002 | 冻结权威规划事实 | 同一轮冻结已发布剧本、动作、资产、型号、设备能力、拓扑和执行点；缺少唯一关系时转人工，不猜测 | P0 |
| REQ-RSP-003 | 受控选择或生成候选 | 先确定性筛选；仅在门禁齐全时最多调用一次模型；模型只能选择冻结候选或组合冻结动作 | P0 |
| REQ-RSP-004 | 编译并物化可确认剧本 | 参数、目标、执行位置和依赖通过确定性校验；临时剧本保存后回读摘要一致；无效候选不能进入确认 | P0 |
| REQ-RSP-005 | 完成整体剧本确认与授权绑定 | AI Console 请求认证；只接受 `approve`、`reject`、`request_revision`；批准绑定当前候选版本和固定执行摘要 | P0 |
| REQ-RSP-006 | 安全、幂等地提交 SOC | 仅在确认绑定有效时走 strict manual；持久化外部调用账本和幂等键；崩溃、超时或重复回调不产生重复执行 | P0 |
| REQ-RSP-007 | 监控技术结果与业务效果 | 按持久化退避查询实例、节点和拓扑；区分技术执行与业务效果；证据不足时输出 `INCONCLUSIVE` | P0 |
| REQ-RSP-008 | 处理缺失事实、外部失败与恢复 | 超时、协议错误、状态未知、目录不可用、关系不唯一等均保留证据并安全失败或转人工，不静默降级 | P0 |
| REQ-RSP-009 | 守住权限与副作用边界 | 规划层零副作用；租户不能由输入覆盖；Prompt 注入、伪造批准、集合外动作和绕过确认请求全部阻断 | P0 |
| REQ-RSP-010 | 提供可审计、可解释的结果 | 来源、快照、候选、确认、提交、节点和效果可关联；不泄露凭据；不把已提交、技术成功或消息成功互相冒充 | P1 |

## 4. 输入与输出

- 输入：受信来源结果引用；来源服务认证信息；事件幂等标识；AI Console 对完整候选的整体决策；必要的会话查询。
- 必需上下文：来源结果版本与摘要、固定租户、权威资产与执行点关系、剧本与动作目录、参数 Schema、能力事实、候选与确认绑定、外部调用账本和 SOC 实例状态。
- 输出或动作：创建可恢复处置 Case；生成一个已发布或临时候选；等待整体确认；向 SOC strict manual 路径提交；输出节点技术结果、业务效果和审计标识。
- 对外入口：`POST /api/v1/agents/response-disposition/invoke`；`POST /api/v1/cases/{caseId}/playbook-decision`。

## 5. 非目标

- 不在 Workspace 规划 Agent/Skill 中直接创建、修改、执行、取消或回滚 SOC 对象。
- 不把模型输出、用户消息内联 JSON、过期缓存或名称相似度当作权威事实。
- 不替代威胁分析、故障排查、巡检或通用资产管理能力。
- 不在缺少唯一资产关系、管理端点、网络执行点或批准绑定时“尽力执行”。
- 不将 SOC 已接收、节点技术成功、业务效果达成、AI Console 消息送达视为同一状态。
- 本轮不发布，不修改业务代码，不执行 50 条真实会话 Trial。

## 6. 依赖与约束

- 内部依赖：`ai-core`、`ai-orchestration`，由 `ai-workbench-server` 组装，数据库迁移归 `ai-init`。
- 外部依赖：受信来源服务、SOC MCP/接口、AI Console、AgentGov 规划接口、数据库、Worker 和部署凭据。
- 模型约束：只在确定性选择不足且所有门禁成立时最多调用一次；不能发起第二轮模型、子 Agent 或工具探索。
- 执行约束：自动确认默认关闭；SOC 监控初始轮询默认 5 秒、最大间隔 300 秒、截止时间默认 86400 秒。
- 配置约束：地址和凭据只从部署配置注入，不允许 Demo、Mock 或环境写死值。

## 7. 已知风险与限制

- 具体模型、采样参数、AgentGov/SOC/AI Console 制品版本、数据库快照和目标环境配置尚未冻结，当前 Baseline 不能复现完整真实链路。
- 50 条 Case 是按代码证据构造的技术候选集，未由响应处置业务人员逐条签字，也未执行正式 Trial。
- 原生单元测试主要验证模块契约，不能单独证明目标环境认证、租户隔离、真实 SOC 幂等、网络超时恢复和处置效果判断。
- 响应动作可造成真实业务影响；任何发布候选都必须完成 R3 独立复核、目标环境安全演练、回滚验证和正式结果留证。
