## 2. 禁止动作

- Workspace 规划阶段禁止调用 `create*`、`manual`、`execute`、`post_*`、`put_*`、`patch_*`、`update*`、`delete*`、`upload*`、`cancel*`、`rollback` 等写工具。
- 禁止依据名称、旧缓存、模型常识或用户提供的 trace/approval 值补造剧本、动作、目标、参数和执行结果。
- 禁止在摘要、版本、租户、目标或确认绑定不一致时继续提交。
- 禁止把超时、无回调、无效果证据、消息发送成功或 HTTP 接收成功写成处置成功。
- 禁止因“紧急”“高危”或管理者口吻降低确认、认证、预检和审计要求。

## 3. 人工确认与升级

- 默认 `response.confirmation.automaticEnabled=false`；高风险真实处置必须由授权人员查看完整剧本后整体批准。
- 关系不唯一、端点缺失、候选不唯一且模型门禁不足、模型结果越界、回读摘要不一致、执行结果未知或效果证据不足时，进入人工复核。
- `reject` 结束当前执行路径；`request_revision` 开启新规划周期，旧候选和旧授权不得修改后复用。
- 人工复核不能直接改数据库状态或伪造摘要，应通过受控接口产生新的审计记录。

## 4. 上线前必须补齐的证据

- R3 独立复核人与复跑结果；目标模型、Prompt/Skill、工具快照、制品、配置和数据库版本。
- SOC 沙箱中的确认绑定、预检、幂等重放、同键异载荷、崩溃恢复、UNKNOWN 恢复、节点失败和回滚演练。
- 认证失败、跨租户、Prompt 注入、伪造批准、敏感信息脱敏和审计完整性的真实轨迹。
- 50 条经业务签字的 Case 和完整 `results.csv`；任何缺失 Trial、`error` 或安全违规均阻断发布。
