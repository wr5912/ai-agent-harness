# 智能体需求定义

> 文档状态：试交付评审稿。本文描述 `main@d74cf6387a2e816637dd2efe2eb2a38deb6b8816` 的策略配置智能能力，不代表正式 Eval Trial 或发布验收已经通过。

## 1. 基本信息

- Agent 名称：策略配置智能能力（Policy Configuration Capability）。
- 当前承载方式：Workspace 主智能体调用专用 `policy-configuration` MCP，由 Workbench V2 确定性编排；最新代码明确不再委派旧 `policy-operator` 子智能体。
- 需求版本：`policy-configuration-requirements-trial-v0.1`。
- 交付负责人：由项目团队指定。
- 材料整理：周洋、Codex。
- 发布执行人：`N/A`，本轮不发布。
- 风险等级：高。完成批准后可能触发真实 SOC 策略写操作，最低复核等级 R3。

## 2. 用户与问题

- 主要用户：SOC 安全运营人员、策略管理员及使用 AI Console 的授权操作人员。
- 用户目标：用自然语言新增、修改或删除网络策略；在有歧义时选择权威候选；查看唯一完整草案；在同一会话内明确批准；查询最终状态和证据。
- 当前实现：Workspace 负责意图路由、字段补齐和对话；`ai-policy` 负责认证、幂等、权威对象解析、候选冻结、草案、摘要绑定、审批、状态机与执行能力门禁；AI Console 负责会话入口和结构化决策转发。
- 核心问题：策略变更有真实副作用，必须把操作人、租户、意图、候选、草案摘要、人工批准和外部执行严格绑定，并在能力缺失、超时或结果未知时安全失败。

| REQ-POL-001 | 路由并归一策略意图 | 识别 ADD、MODIFY、DELETE；补齐 V2 必需字段；信息不足只追问，不误调用其他智能体或策略工具 | P0 |
| REQ-POL-002 | 认证且幂等地准备任务 | 主体、租户和请求合法；同幂等键同载荷复用、异载荷冲突；未经认证不创建任务 | P0 |
| REQ-POL-003 | 解析并冻结权威候选 | 从受控目录解析对象；零候选安全失败，多候选显式选择；不得由模型或用户自由文本伪造权威 ID | P0 |
| REQ-POL-004 | 绑定候选与稳定摘要 | 只接受当前任务候选；选择后重算并冻结摘要；过期、越界或篡改候选被拒绝 | P0 |
| REQ-POL-005 | 生成唯一可确认草案 | 只物化一个 `DRAFT`；保存后回读一致；完整展示操作、对象、字段和固定摘要 | P0 |
| REQ-POL-006 | 完成同会话结构化决策 | 按 `[status] → decide(APPROVE) → result`；批准需认证、同会话、同主体并绑定当前摘要；拒绝和修订不执行 | P0 |
| REQ-POL-007 | 守住真实执行边界 | 执行前必须通过能力、批准和状态门禁；目标 SOC 能力不可验证时明确报告能力缺口，不降级到旧链或模拟成功 | P0 |
| REQ-POL-008 | 提供持久状态与安全恢复 | 支持 `prepare → status → [select → status] → result`；重复查询无副作用；超时、崩溃和未知结果不盲目重提 | P0 |
| REQ-POL-009 | 保持最小权限并退役旧链 | Workspace 不暴露 `policy-control`；旧 `policy-operator`、旧 Preview 四工具和旧 Hook 不可路由、不可激活 | P0 |

## 4. 输入、协议与输出

- 用户输入：新增、修改或删除策略的自然语言请求；候选选择；批准、拒绝、修订或结果查询。
- 规范意图：`operation`、`source`、`destination`、`protocol`、`destination_port`、`action`、`target_external_id` 等 V2 字段；MODIFY/DELETE 必须具有权威目标标识。
- MCP 工具：`prepare_policy_configuration`、`get_policy_configuration_status`、`select_policy_configuration_candidate`、`get_policy_configuration_result`、`decide_policy_configuration`。
- 标准流程：`prepare → status → [select → status] → result`；批准流程为 `[status] → decide(APPROVE) → result`。
- 输出：缺失字段问题、候选列表、完整草案、当前状态、能力缺口或最终结果；不得把中间态表述为已执行成功。

## 5. 非目标

- 不恢复或继续使用旧 `.claude/agents/policy-operator.md` 作为线上子智能体。
- 不允许 Workspace 或模型直接持有 `mcp__policy-control__*`、SOC 原始写接口或任意 CRUD 权限。
- 不依据名称相似度、模型常识、用户自报身份或内联 JSON 伪造权威对象。
- 不在缺少目标 SOC 已批准单动作接口时降级到 Ingest Preview、旧图谱编排、Mock 或重复模型重试。
- 不把 `DRAFT`、`APPROVED`、HTTP 接收或消息送达等同于外部执行成功。
- 本轮不改业务代码、不发布、不执行 50 条真实对话 Trial。

## 6. 依赖与约束

- Workspace：`ai/security-operations-expert/workspace`，负责路由、字段收集和受限 MCP 调用。
- Workbench：`ai/ai-workbench/ai-policy`，负责确定性策略状态机和安全门禁。
- Console：`ai/ai-console-service/src/policy-configuration`，负责会话与结构化决策入口。
- 外部依赖：身份与租户上下文、权威策略目录、目标 SOC 已批准执行接口、数据库和部署凭据。
- 版本约束：本交付只适用于 Workbench Policy Configuration V2；磁盘中旧文档或兼容文件存在不表示其可线上路由。
- 配置约束：地址、身份和凭据只能由部署配置注入，用户输入不得覆盖。

## 7. 已知限制

- 当前代码契约要求的目标 SOC 已批准单动作执行能力尚不可验证；门禁应返回外部能力缺口并停止，不能据此宣称端到端执行成功。
- 模型、采样参数、目标部署制品、外部目录快照、数据库和正式环境配置尚未冻结。
- 50 条 Case 均为依据最新代码构造并完成技术复核的候选用例，尚未由策略业务负责人逐条签字，也未运行正式 Trial。
- 单元测试只能证明代码契约，不等于真实租户隔离、网络超时、外部幂等、真实策略效果和回滚已验收。
