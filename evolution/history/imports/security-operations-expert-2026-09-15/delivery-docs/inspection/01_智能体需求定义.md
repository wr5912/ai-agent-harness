# 智能体需求定义

> 文档状态：试交付评审稿。本文描述 `main@e61016b71deaa377cc0d0634777dce97229067f1` 的现有巡检能力，不代表正式自测或交付评估已经通过。

## 1. 基本信息

- Agent 名称：巡检智能体（Inspection Agent）
- 需求版本：`inspection-requirements-trial-v0.1`
- 交付负责人：待团队指定
- 开发成员：周洋（材料发起人，身份待本人确认）；Codex（材料整理）
- 发布执行人：`N/A`，本轮不发布
- 风险等级：低（只读取证与报告生成，不执行真实业务写操作）；最低复核等级 R1

## 2. 用户与问题

- 主要用户：安全运营人员、运维人员，以及通过 security-operations-expert 会话入口发起巡检的授权用户。
- 典型触发场景：例行检查资产在线状态与漏洞；按指定能力或范围巡检；检查已知网络关系或指定两端 IP 的可达性；获取确定性结论和 HTML 报告。
- 当前处理方式：会话侧委派给巡检子智能体；子智能体只调用 Workbench 暴露的 4 个高层巡检工具，运行时位于 `ai/ai-workbench/ai-inspection`。
- 主要问题：把自然语言稳定映射到固化能力目录和服务端状态机，在不直连 SOC、不猜测参数、不改写结果的前提下完成取证闭环。

## 3. 目标任务与成功标准

| 需求 ID | 目标任务 | 可验证的成功标准 | 优先级 |
|---|---|---|---|
| REQ-INS-001 | 执行默认例行巡检 | 泛化巡检请求使用 `group_code=routine`、`scope.type=all` 并省略 `capabilities`；不要求非必需补充信息 | P0 |
| REQ-INS-002 | 按显式分组、能力或参数执行巡检 | 最多查询一次实时能力目录；只使用目录存在的能力 ID、参数和 Schema，不猜测 | P0 |
| REQ-INS-003 | 在用户授权范围内执行 | 默认范围为 `all`；显式范围必须符合实时 Schema；租户、Workspace、主体不能由请求覆盖 | P0 |
| REQ-INS-004 | 输出可判定的结论与报告 | 仅在服务端允许 finalize 后定稿；最终正文逐字返回 `user_response_markdown`，报告地址与工具结果一致 | P0 |
| REQ-INS-005 | 按状态机安全推进并处理失败 | 始终复用真实 `run_id` 并遵循 `next_action`；错误、超时、部分成功或状态不明时如实停止，不走替代通道 | P0 |

| REQ-INS-007 | 拒绝会话能力之外的请求 | 不执行历史列表、计划任务 CRUD、复杂根因分析、隔离/删除/修复等写操作，并给出正确入口或转交方向 | P1 |
| REQ-INS-008 | 校验缺失、噪声和非法输入 | 对可安全消歧的口语和噪声正常处理；对单端点、非法 IP、未知能力、额外字段等停止并说明可操作原因 | P0 |

## 4. 输入与输出

- 输入：用户自然语言；可选的分组、能力、范围、网络路径两端 IP 和能力目录允许的参数。
- 必需上下文：实时能力目录；部署固定 tenant/workspace/principal；服务端返回的真实 `run_id`、`next_action`、状态、覆盖率和最终结果。
- 输出或动作：创建巡检计划、分轮聚合取证、确定性定稿；向用户返回服务端生成的 `user_response_markdown` 和其中的报告地址。Agent 不直接返回原始取证明细。

## 5. 非目标

- 不查询历史运行、历史报告列表或趋势，不管理定时巡检任务；这些能力属于页面/API 管理面。
- 不做复杂根因推断、跨证据关联或复杂处置建议，应转故障排查智能体。
- 不执行隔离、封禁、删除、策略修改、自动修复等业务写操作。
- 不直连 SOC、资产系统、数据库或任意公网，不使用 Bash、文件系统或其他 MCP 作为失败兜底。
- 不承诺已经实现完整租户隔离、细粒度权限、合规审计或模型分析。
- 本轮不执行发布、远端部署验收或 50 条真实会话正式自测。

## 6. 依赖与约束

- 数据或系统依赖：Workbench `ai-inspection` 与 `ai-bff`；MCP 管理平台从 Workbench OpenAPI 发布 4 个工具；SOC 资产、漏洞、网络关系上游工具；数据库/Liquibase；报告存储与公共下载配置。
- 性能或成本约束：任务默认总超时 300 秒、单项 60 秒；资产页默认 100、最大资产数 10000；并发默认 6、最大 32；切片默认 50、最大 500；每轮 collect 默认最多推进 2 片、最大 8；网络关系默认上限 2000。
- 运行范围：会话控制面 `/api/v1/inspection-control`，Web 管理面 `/api/workbench/inspection`，报告下载 `/reports/inspection/{runId}/{reportId}`；Worker、scheduler 和能力发现默认关闭，须由部署配置启用。

## 7. 已知风险与限制

- 会话模型为 `model: inherit`，具体模型和版本不在仓库中固化；正式 Baseline 前必须冻结目标环境模型。
- 控制 API 当前按内网匿名方式部署，依靠固定 service 身份配置；若网络边界失守，缺少应用层凭据会扩大风险。
- 公共报告依赖同时不可猜测的 `runId` 与 `reportId`，但仍需由部署侧保证链接传播、日志和网络访问边界。
- 当前 50 条 Case 为代码证据驱动的研发侧候选稿，尚无业务复核签字、真实环境 Trial 和历史生产失败清单。
- 当前 Workspace 巡检定向测试有 7 项失败：新旧巡检配置存在残留不一致，且部分包含“高危漏洞/离线资产”的自然巡检输入会被错误路由到故障分析；该问题直接影响 REQ-INS-001/002/007，修复前不得判定交付通过。
- 本轮只能证明材料结构与部分本地代码检查结果；不能据此声称智能体整体交付通过。
