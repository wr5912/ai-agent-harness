# AI 纠错自动记录

用户输入若是对上一轮的纠错，就在**本轮回复完成后**追加一条极简记录。全程不打断正常回复。

## 判定是否算纠错

- **算**：明确否定（不对、错了、不是这样）；指出具体错误（漏了、理解错、格式错、逻辑错）；要求修正（应该是、改成、重新做、必须加上、禁止）。
- **不算**：新问题、新任务；继续、展开、再详细点；确认、感谢、闲聊。
- 低置信默认不记录。用户提出问题或质疑但未指出错误时，按新任务处理。

## 流程

1. 用户输入判为纠错后，在本轮上下文里暂存：上一轮用户输入要点、上一轮 AI 输出要点、本轮纠正内容、当前时间。暂存不落盘。
2. 正常完成本轮回复；回复本身不因记录而变长。
3. 回复末尾抽取 7 个必填字段。`AI反思` 优先取本轮回复中已写明的反思，没有则据实际过程生成。
4. **只调用一次**写入脚本（同一轮纠错只写一次）：

   ```bash
   python3 .agents/skills/ai-correction-log/scripts/record_correction.py --file - <<'JSON'
   {"原提问要点":"…","AI错误要点":"…","我的纠正要点":"…","AI反思":"…","根因":"…","改进方法":"…","标签":["格式错误"]}
   JSON
   ```

5. 脚本输出 `{"status":"appended",…}` 即完成；输出 `skipped-duplicate` 表示当天已写过同一纠错，不要重复尝试；非零退出必须原样告知用户。
6. 本轮回复失败或被中断时，不写记录。多个独立根因可拆 2～3 条，同一根因只在首条记 `根因`。

## 摘要化（硬要求）

- 不复制原提问全文、不复制 AI 完整回答、不记未被纠正的正确内容与寒暄。
- `原提问要点`：只留被违反的原始要求或约束。
- `AI错误要点`：只留错误点或错误片段。
- `我的纠正要点`：只留修正要求。
- `时间` 省略时脚本按本机当前时间填写；日期决定写入哪一天的 JSONL。
- 字段上限：要点类 ≤200 字，`AI反思`／`根因`／`改进方法` ≤300 字，全部单行；`标签` 最多 5 个、每个 ≤20 字。
- 只允许 7 必填 + 1 可选字段，不新增字段。

| 字段 | 必填 | 说明 |
|---|---:|---|
| `时间` | 是 | 记录时间，`YYYY-MM-DD HH:MM`；可省略，脚本自动取当前时间 |
| `原提问要点` | 是 | 只保留被违反的原要求或约束 |
| `AI错误要点` | 是 | 只保留被纠正的错误点 |
| `我的纠正要点` | 是 | 只保留用户的修正要求 |
| `AI反思` | 是 | 优先从本轮 AI 回复提取，否则据过程生成 |
| `根因` | 是 | 具体原因，不写“模型不行”“能力有限” |
| `改进方法` | 是 | 下次可执行的避免方法 |
| `标签` | 否 | 如 `翻译`、`格式错误`、`遗漏约束` |

## 失败与安全

- 脚本检测到疑似密钥、令牌、凭据或带凭据的 URL 会拒绝写入：改写要点，绝不复制原文。
- 同一 `(原提问要点, AI错误要点, 我的纠正要点)` 当天已存在时脚本跳过，不重复写入。
- 写入失败、当天文件损坏时脚本非零退出并说明原因，必须告知用户，不静默丢弃。
- 记录文件随仓库版本控制，按天追加；不得重写或删除既有记录。

## 示例

```json
{"时间":"2026-09-17 10:30","原提问要点":"翻译成英文，保留术语表，表格输出","AI错误要点":"漏掉术语“召回率”；未用表格","我的纠正要点":"术语表必须全部保留；输出必须用表格","AI反思":"生成前未提取硬约束，输出前未逐项核对","根因":"把术语表和表格格式当成软要求，没有做硬约束校验","改进方法":"生成前列硬约束清单，输出后逐项核对；术语表强制匹配","标签":["翻译","遗漏约束","格式错误"]}
```
