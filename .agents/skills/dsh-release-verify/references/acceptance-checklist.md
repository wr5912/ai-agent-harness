# DSH Release 验收清单

## 身份链

记录并逐一比对：

| 层级 | 必需证据 |
|---|---|
| 交付评估 | `baseline_id`、采用的 `run_id`、结论、不可变结果快照 |
| Release | 版本、Artifact 路径或 URI、内容摘要、Runtime 兼容范围、评估报告、变更记录 |
| 宿主机 | 实际挂载源、文件清单、摘要、权限和属主 |
| 容器 | 镜像 digest、DSH/Runtime 版本、目标路径、挂载模式、文件清单和摘要 |
| Runtime | 实际 profile、展开后的配置、加载成功/失败证据和资产身份 |

只要上述身份无法闭合，就不能声称运行的是评估通过的 Release。`current/` 若存在，只可作为发布后与同一 Release 一致的镜像，不能替代具体 Release 身份。

## 完整任务链

按 Agent 能力选择至少一条代表性链路，并保留：

1. 对外实际入口、认证身份和请求；
2. 实际 Agent/Session 或等价运行标识；
3. Tool、MCP、数据源及审批的真实调用结果；
4. 用户可见输出；
5. 最终业务状态；
6. 必要的审计或 Trace 关联；
7. 超时、失败、部分成功或状态未知时的停止/回滚结果。

如果该 Release 包含中、高风险控制，链路不得绕开其服务端或 Runtime 强制点。不得用模拟入口替代对外协议，也不得以静态测试结果替代容器内真实加载和执行。

## 结果表述

- `局部存活`：仅能证明进程、端口、HTTP 或健康检查。
- `挂载可见`：仅能证明容器看到文件。
- `资产已加载`：有 Runtime 配置、诊断或可观察行为证明加载了匹配摘要的 Release。
- `完整业务链通过`：实际协议、依赖、结果、最终状态与审计均满足冻结验收标准。

只有身份链闭合、资产已加载且完整业务链通过时，才能形成发布验证通过的事实；否则精确报告失败点或证据缺口。
