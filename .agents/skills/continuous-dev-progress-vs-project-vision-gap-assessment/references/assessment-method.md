# 远景进展评估方法

## 固定评估基准

目标默认取本仓库 `docs/DSH智能体运行管理平台设计方案.md` 的指定提交。记录目标文档、版本、选定情境、纳入与排除项，以及条件能力是否纳入。只将该情境中明确要求的能力计入分母；互斥方案只计被选方案。必要但原文未明确的推导项单列依据，未经确认不静默计入正式目标。目标范围无法明确时输出任务草案和待确认项，不声称得到完整远景的精确进展率。

实现基准记录代码提交、工作树状态及纳入的差异；默认只评估 `HEAD`。方法基准记录本技能版本及本次任务拆分、标准和权重。历史报告、检查范围和无法读取的来源也要列明。连接远端时，以实际读取的提交为准，不混用两个时间点的文件。

## 任务拆分与唯一归属

从目标情境向下拆为架构分区、功能域、模块和可验收任务。任务有稳定编号、唯一所属模块、目标行为、可观察完成标准、目标依据与权重。职责粒度尽量相近；同一能力在图中多处出现也只统计一次。条件能力注明条件。外部 DSH Runtime、模型和第三方工具本身不计为本仓库完成量；本项目需要的接入、控制、观测和验证任务才进入任务树。

在看当前实现前固定任务及权重。默认同级原子任务等权；不等权时先说明依据。若将任务细分，子项权重之和保持原任务权重，父项只汇总而不重复计分。目标行为不同，所需验证也不同：源码存在或 CLI 可用只能支持所覆盖的子项，不能自动证明平台界面、真实会话或多用户行为。

## 证据与状态

对每个任务分别写实现情况、证据类型、目标确认情况、差距性质和当前阶段影响。证据引用应包含位置、提交或运行时间、实际证明的行为和适用限制。沿具体主张读取代码、配置、调用方、测试和原始记录；旧 Run 须核对当时来源、镜像、模型、环境及目标标准。静态合同、容器就绪、真实运行与业务效果各自只证明对应层级。

目标判断只用三类：已确认满足、已确认未达、待核实。未找到证据或无法访问资料属于待核实，不能写成未开展；已有实现但未做必要验证时，可确认“验证工作尚缺”，但其运行效果仍待核实。差距性质可说明建设、集成、验证、需求未定或证据访问受限。远景差距另写当前是否阻塞 Research Mode、近期是否值得做，以及触发远期建设的具体条件；颜色和低百分比不决定优先级。

## 计算

令每个唯一原子任务的权重为 `wᵢ > 0`，完成标准中已确认满足、已确认未达和待核实的权重比例分别为 `cᵢ`、`mᵢ`、`uᵢ`，三者之和为 1。未细分的原子任务取 `(1,0,0)`、`(0,1,0)` 或 `(0,0,1)`；部分完成须来自事先定义的验收子项，不能主观折算为 50%。

```text
W = Σwᵢ
P = 100 × Σ(wᵢcᵢ) / W    已确认进展
G = 100 × Σ(wᵢmᵢ) / W    已确认差距
U = 100 × Σ(wᵢuᵢ) / W    待核实
P + G + U = 100%
```

整体、功能域与模块均对其所属任务直接汇总，不能平均模块百分比。先用未舍入值计算，再统一展示精度。有未知项时显示“已确认进展至少 P%｜已确认差距 G%｜另有 U% 待核实”；`100%-P` 不能全部称为已确认差距。若给区间 `[P,P+U]`，须注明它只是未知项的可能上下界。分母不明确时不计算整体数值。

## 跨次比较

没有历史报告时只给本次基线。仅在目标范围、完成标准、权重和方法相同，或把两次状态按明确的共同范围重算后，才比较百分比。后续可用上次任务编号和代码差异定位复核，但共享配置、Runtime 锁、模型和评估标准变化也可能使旧证据失效；未复核的受影响任务转为待核实。

分别说明实现变化、证据变化、目标变化和方法修正。补证据带来的进展不写成新开发成果；分母变化不写成开发进退。证据不足时说明不可直接比较，不编造趋势。历史报告是时间点产物，不是可手改的目标来源；当前事实仍以对应版本的原始资料为准。
