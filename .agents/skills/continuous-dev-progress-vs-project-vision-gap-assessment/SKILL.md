# 持续开发进展与远景差距评估

“持续”指多次显式盘点与可比分析，不启动后台任务。未来平台目标是进展参照；当前仓库仍按 Research Mode 运作，远景差距不自动成为当期缺陷。

## 开始

读取当前版本的根级 `AGENTS.md`、`docs/standards/SOURCES.md`、`docs/standards/PROJECT-INTERPRETATION.md`、`docs/项目审查原则.md`、`docs/ai-agent-harness项目验收矩阵.md` 和用户指定的目标文档。默认目标来源为 `docs/DSH智能体运行管理平台设计方案.md`。参考图只供布局参考。

分析前读取[评估方法](references/assessment-method.md)；制作产物前读取[呈现约定](references/presentation-spec.md)。以相应版本的源码、配置、原始运行记录和目标文档判断事实，旧报告与 Memory 仅作线索。

## 执行

1. 固定目标版本、适用情境、实现提交、工作树是否纳入、方法版本和检查覆盖。默认评估 `HEAD`；仅在用户明确要求或任务明确指向工作树时纳入未提交改动，并标明差异。
2. 由未来目标建立唯一的分区、功能域、模块与可验收任务树。先固定完成标准与权重，再核对实现。范围无法确定时列出待确认项，不给完整远景的精确百分比。
3. 沿每项完成主张核对实际调用链、配置、测试与运行证据；无法核实的目标任务保留在范围内并计为未知。区分上游 DSH 能力与本仓库的接入和验证。
4. 按评估方法汇总已确认进展、已确认差距与待核实比例，分别说明远景差距、当前阶段影响和建设启动条件。有历史报告时仅比较可比范围，并说明实现、证据、目标与方法的变化。
5. 先完成 `任务拆分说明.md` 的任务、数值与来源，再从同一份结果生成 3840×2160 的 SVG。逐项核对图文编号、数值、文字、连线、可读性和文件存在性。

默认输出目录为 `/tmp/project_vision_gap_assessment/` 下不覆盖旧文件的本次子目录；用户指定路径时使用指定路径。默认交付 `任务拆分说明.md` 和 `AI-Agent-Harness-未来平台架构与当前进展映射图-4K.svg`。报告是本次分析产物，不另建可手改的状态台账。

## 边界

- 百分比只表示本次明确的未来目标范围，不表示工时、当前研究阶段完成率或生产就绪度。
- 不把目标文档以外的通用市场、灰度发布、审批平台等设为默认要求；Research Decision 与未来业务版本切换分开表达。
- 不修改项目事实源、自动整改、启动业务实例、执行真实业务评测、提交或发布。若本次请求另有明确授权，按其范围执行。
- 绘图能力不足时保留可完成的分析结果，并明确说明 SVG 未完成；不以提示词或草图冒充交付。
