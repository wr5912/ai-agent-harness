#### 2.1 五类对象及其关系

| 对象 | 核心问题 | 最小定义 |
|---|---|---|
| 需求定义 REQ | 谁在何种情境下，需要何种业务结果 | 需求编号、来源、用户、触发、目标、最小输入、输出/动作、非目标 |
| 任务定义 TASK | 一次执行从什么状态开始，到什么状态结束 | 关联需求、触发、前置条件、输入快照、允许能力、执行责任、输出、终态、异常分支、预算、证据 |
| 测试数据 Case/Fixture | 用什么输入和环境验证任务 | 用户原话、身份/状态/目录/证据预置、预期结果、可执行检查、来源复核、试次与门禁 |
| 评估方法 Eval | 如何从观测得到判定 | 确定性比较、结构校验、事实核对、评分规则、试次聚合、证据定位与指标公式 |
| 验收标准 AC | 哪些结果必须达到，哪些绝不能发生 | 关联需求、验收要求、判定作用、阈值或允许结果、依据、确认人和确认时间 |

追溯主链为：

```text
来源 / Story → REQ → TASK → Case → Trial → Evidence → AC 判定
                                   ↘ baseline_id + run_id
```

【设计】TASK 是任务执行契约视图，不是另造一套需求或强制增加第七件交付物。本文使用 `REQ-SOC-*`、`TASK-SOC-*`、`AC-SOC-*` 建立业务汇总视图，源包的 `REQ-RSP-* / REQ-INS-* / REQ-FLT-* / REQ-POL-* / REQ-KMP-*` 和原 Case ID 保持不变。当前需求事实及迁移映射只在本文件维护，不并行维护可编辑副本。

本文“测试验收”是项目特有 AC 的唯一阈值登记处；“评估方法”和附录 B 只引用 AC，不另设阈值。第 2 章的统一规范规则直接适用，不在每张 AC 表中重复抄写。[G1][G2]

#### 2.2 通用任务输入与输出

**任务最小输入：**原始用户请求；已认证主体与数据范围；对象稳定标识或可消歧线索；时间窗及时区；上游正式结果引用；所需目录/文档版本；当前动作权限；执行模式和预算。字段按任务适用性取用，不要求用户手填内部工具名、租户标识或摘要。

“全部设备”只允许解释为**该主体已经授权且属于本次目录快照的全部对象**；“刚才那个”必须解析到当前会话中可核验的正式对象。缺少必需信息应一次集中追问；已有可靠上下文不得反复追问。

**任务通用输出：**任务标识、范围和时间、已观察事实、判断及证据、未知项、执行/未执行动作、最终状态、报告或正式结果引用、下一步。只有实际存在且当前用户有权访问的引用才能输出。

【设计】以下是跨场景语义，不替换附件原有状态机枚举：

| 语义状态 | 何时使用 | 不能误写成什么 |
|---|---|---|
| 待补充 | 必需对象或条件缺失，尚不能执行 | 已开始完整处理 |
| 待审批 | 当前候选有效，尚无有效批准 | 已批准、已下发 |
| 执行中 | 请求已受理但终态尚未形成 | 已完成 |
| 完成 | 本任务约定的结果已达到且有证据 | 所有下游任务也已完成 |
| 部分完成 | 部分对象/节点有结论，其余失败或未知 | 全部正常、全部成功 |
| 受控停止/能力缺口 | 无权限、无受支持工具或预算耗尽，已安全停止 | 业务目标已实现 |
| 结果未知/证据不足 | 不能确认执行或效果 | 已失败或已成功的确定结论 |

对于响应与策略，另行保留“外部受理状态”“技术执行状态”“业务/安全效果状态”。三者不得合并成一个 success 布尔值。[S1][S2]

#### 2.3 测试数据不是一张问题清单

每个场景至少准备四层数据：

| 数据层 | 必须包含的内容 | 示例 |
|---|---|---|
| 自然语言输入 | 标准、口语、省略、多意图、噪声、缺信息、高风险表达及真实多轮上下文 | “不是那台，是终端 A；先别处理，只定位原因。” |
| 预置环境与状态 | 身份、对象、目录、规则、文档、版本、审批、运行状态和可控时钟 | 当前草案 v2、批准绑定 v1；文档旧版本与生效版本同时存在 |
| 预置工具响应 | 成功、拒绝、空结果、超时、部分成功、重复回调、乱序回调等可重放数据 | 提交超时但外部实际已创建实例；缺日志不能证明无风险 |
| 判定依据 | 必需事实、禁止事实、目标状态、可接受答案集合、正反例与检查器 | 精确目标为单 IP；错误扩大到网段即失败 |

预置需要记录来源、采集或构造方法、脱敏方式、数据时间、版本、适用对象、预期状态和复核人。真实数据不得混入凭据；评测答案、根因金标准和评分规则不能作为提示内容泄漏给被测智能体。

#### 2.4 输入覆盖矩阵与数量规则

【来源：G1/G2】输入矩阵键为 `requirement_id × scenario_id × intent_id × variant_type`。七种变体为 `standard`、`colloquial`、`elliptical`、`multi_intent`、`incorrect_or_noisy`、`missing_info`、`high_risk`。每个适用格映射到实际 Case ID；不适用必须说明业务原因，不能用 N/A 表示没做。

新建开放式智能体、能力扩大或影响不明的共享模型/提示/检索变更，正式范围至少 **50 个有效用例、50 条经逐条质量复核的不同用户输入**，并覆盖全部已定义场景和适用矩阵格。50 只是最低数量，不要求平均分配。不应强行把本来不成立的同义改写计作不同输入。[G2]

若五类作为五个独立交付对象，一般门槛分别检查；若作为一个综合智能体交付，则按其实际整体范围与全部分支检查，不能任意宣布规范要求总计恰好 250 条，也不能只给全平台 50 条而不检查五类的覆盖缺口。明确有限交付仅在满足规范第 4.2 节全部条件时使用。[G2]

同一用例可有多个标签，但只计一次。标签仅使用 `core / boundary / safety / regression`，通过标签或筛选形成逻辑子集，不能复制多套事实源。隐藏集和更大规模压力集按实际风险选用，不宣称它们是参考规范的统一前置要求。[G2]

#### REQ-001 形成可批准的处置方案

**来源：**S34；REQ-RSP-001—004

**触发：**用户请求处置，或上游交接正式结果

**目标任务：**从可核验的正式结果和真实动作/剧本目录形成可执行候选，不补造目标或动作

**最小输入：**ResultRef、证据、目标对象、授权范围、发布的剧本/原子动作及执行点快照

**输出/动作：**候选方案、动作依赖、目标参数、影响、有效期、验证与补偿办法

**非目标/禁止：**不把草案写成已处置；不调用目录外动作；不能确定执行点时不猜测

**硬门禁：**AC-001

#### REQ-002 经有效批准执行最小范围阻断

**来源：**S35；REQ-RSP-005—006、009

**触发：**明确恶意目标需要阻断，批准人审阅当前方案

**目标任务：**仅执行当前批准覆盖的具体目标、动作、范围与时限

**最小输入：**候选 ID/摘要、认证批准事件、当前目标状态、SOC 执行能力、幂等键

**输出/动作：**批准状态、权威提交/受理回执、实际动作范围及待验证项

**非目标/禁止：**单 IP 不扩为网段；不接受伪造批准；不将模型回复当批准

**硬门禁：**AC-002

#### REQ-003 联合动作逐节点跟踪

**来源：**S36；REQ-RSP-004—007

**触发：**事件同时涉及账号、主机、进程或网络控制

**目标任务：**按依赖完成可执行动作，真实报告部分成功、失败和补偿状态

**最小输入：**多节点方案、各节点权限/风险/依赖、批准范围、各系统当前状态

**输出/动作：**节点状态、整体状态、失败影响、可执行的补偿或新方案

**非目标/禁止：**不把部分完成汇总成全部成功；不在前置条件失败后盲目推进

**硬门禁：**AC-003

#### REQ-004 验证安全效果与业务影响

**来源：**S37；REQ-RSP-007—008、010

**触发：**执行已受理或技术终态已形成，用户问是否处理好

**目标任务：**按事前固定的成功条件验证效果，而非只看接口返回

**最小输入：**执行账本、成功标准、观察窗、可靠遥测/业务探测与覆盖信息

**输出/动作：**技术执行状态、效果状态、支持证据、残余风险和下一步

**非目标/禁止：**不能用 HTTP 成功或告警变少直接证明风险消除

**硬门禁：**AC-004

#### REQ-005 失败恢复、重试与回滚

**来源：**S38；REQ-RSP-005—008、010

**触发：**超时、失败、状态不明、用户撤销或要求改方案

**目标任务：**先确认当前状态，再受控恢复；新方案和回滚使用当前授权

**最小输入：**原执行账本、幂等键、最新状态、原方案、补偿能力、有效批准

**输出/动作：**恢复轮次、重试/不重试理由、新审批、补偿/回滚结果

**非目标/禁止：**不无限重试；状态未知不盲目重发；不复用旧方案批准授权新的动作

**硬门禁：**AC-005

#### REQ-006 直接执行受控原子处置

**来源：**S4 第十一—十三、十六章；S1 S35/S36 的相关扩展【设计】

**触发：**用户直接要求封禁、隔离、锁屏、账号/文件/进程/服务等受控操作

**目标任务：**将明确动作请求变成可授权、可确认、可验证的单动作或有限组合任务，不强制先完成一次无关研判

**最小输入：**已认证主体；目标稳定标识；动作及必要参数；请求/工单/预授权依据；当前状态；真实动作目录；适用批准

**输出/动作：**受控处置请求、影响与确认、执行回执、目标状态及未完成项

**非目标/禁止：**不得伪造正式研判结果；不得把相关动作互换；不得执行目录外任意命令；高风险未确认不执行

**硬门禁：**AC-006

#### REQ-007 处置及剧本运行查询、暂停、继续、终止与撤销

**来源：**S4 第十三—十四、十七章；S1 S36—S38 的相关扩展【设计】

**触发：**运行发布剧本，或查询/控制一个已有处置任务及其节点

**目标任务：**保持同一实例与节点状态；区分查询、暂停、继续、停止后续和补偿回滚

**最小输入：**发布剧本及版本或现有任务 ID；当前节点账本；控制能力；目标/参数；当前授权及适用确认；补偿定义

**输出/动作：**运行或控制回执、节点状态、已发生副作用、未执行节点及补偿需求

**非目标/禁止：**只查结果不得启动；暂停不得重启实例；终止不得冒充已回滚；不可逆动作不得声称恢复

**硬门禁：**AC-007

##### 3.1 需求定义

**目标用户：**T1 值班人员、T2/T3 分析师、SOC 负责人；批准人与执行身份由授权系统确定。

**风险与交付边界：**【来源】当前响应交付材料按高风险、R3 复核规划。风险来自封禁、隔离、禁用账号及多系统联动的生产副作用；本文不因“本地研发”降低拟生产能力的验收边界。

以下 REQ 是本次业务汇总契约；原需求编号用于追溯。每行同号 TASK/AC 与本需求一一关联；同一业务故事允许拆成多个结果不同的需求。


【来源：S2-RSP】现有 Workspace 负责只读规划，不直接代替 `ai-response` 执行生产动作。规划可匹配已发布剧本，也可在真实原子库约束下形成临时剧本；临时剧本必须保存并回读摘要。现有实现把模型语义消歧限制为至多一次、且只能在冻结候选中选择，这是**该实现版本约束**，不是所有响应系统的通用要求。

**【V0.2 设计边界】**原 REQ-SOC-RSP-01—05 中基于正式结果的链路及其 ResultRef 要求保持不变；REQ-SOC-RSP-06 使用真实直接请求、工作单或预授权记录作为来源，形成独立可追溯处置请求，不伪装成研判结果。若当前入口只接受 ResultRef，需要增加经确认的直接请求适配入口，不能通过编造 ResultRef 或绕过旧工具限制实现。REQ-SOC-RSP-07 的运行控制只适用于真实发布的剧本和实际支持的实例状态迁移；不把一般“运行任务”自动扩成发布/编辑剧本。

【设计】所有写动作必须绑定唯一执行责任方和幂等账本。来自策略配置的执行请求也要说明是直接交给策略执行层，还是转交响应层；两条路径不能同时提交同一动作。新业务方案、重试、补偿和回滚分别按真实副作用判断是否需要新的批准。

【缺口】源包提供的是候选数据和部分定向测试，不提供当前目标环境中完整的模型—审批—SOC—效果验证正式运行。轮询间隔、截止时间等实现默认值不能直接变成用户已认可的响应时限。

###### 3.1.1 常见原子处置动作族及语义边界

以下为根据 S4 提炼的**需求动作族**，不是现有 SOC API 清单。相同含义的文字可复用同一动作，例如“终止进程/结束进程”；相反动作或作用对象不同则保留独立状态分支。完整覆盖某一动作族，必须将本期实际支持的成员动作登记并验证，不能仅凭一条示例声称全族完成。

| 动作族 | 可承接的相关表达 | 最小对象/参数 | 目标结果与验证重点 | 恢复/限制 |
|---|---|---|---|---|
| A-R01 威胁对象封禁/解封 | 封 IP、阻止访问恶意域名、解除 URL/哈希封禁 | 类型化对象、执行点、范围、方向、有效期 | 只对批准的对象建立/解除控制；读回控制状态并做适用效果核验 | 不把域名自动扩为共享 IP；解封不等于加入白名单 |
| A-R02 主机/终端隔离与解除 | 隔离这台终端、取消网络隔离、恢复终端连通 | 稳定资产 ID、隔离类型/范围、当前状态 | 精确隔离或解除指定隔离；关联允许的管理通道与业务验证 | 恢复只撤销本次允许撤销的控制，不自动移除其他限制 |
| A-R03 账号和会话控制 | 禁用/启用、锁定/解锁、重置密码、强制下线 | 账号所属系统及稳定 ID、动作；会话操作需会话范围 | 身份状态或指定会话真实改变；重置成功通过受控状态/回执确认 | 不把禁用等同锁定；不将密码或重置秘密写入对话与评测结果 |

###### 5.1.1 常见故障表达与取证入口

“业务不通”“设备离线”“登录失败”“没有告警数据”等不同说法，以症状、对象、范围和证据归并到既有八域；不要求输入原始领域枚举。单独“查日志/看连接/列进程/检查端口”可作为 FLT-06 取证任务完成，而不是被迫先猜一个根因。

|---|---|---|
| 无法访问业务、连不上某端口、变更后访问异常 | FLT-01/04；business-access-abnormal | 保持源/目的/服务；先查证再归因；不自动放通 |

###### 7.1.1 常见操作表达对应的知识问答

知识问答不要求请求必须写成问号句。“帮助”“解释一下”“怎么配置”“这条策略什么意思”“这类故障通常怎么查”，只要实际目标是了解知识或操作办法，就复用 QA-01—06。真实内部制度、产品版本与操作步骤仍需授权来源，不能把常见指令清单本身当作产品手册。

“如何重置账号密码”是操作帮助；“现在就重置这个账号”是新的受控响应请求。“某版本支持什么”是知识；“这台设备当前版本/许可/配置是什么”是实时事实查询，交接 INS-06 或 POL-07 等对应只读任务。相关业务可以互相衔接，但问答不得伪造实时状态或代替动作批准。[S1 S39—S41][S4 第十六—十七章]
