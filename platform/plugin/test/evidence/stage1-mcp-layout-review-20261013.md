# MCP 页面专项审查与整改

审查基准为 `e4860eb28b9ee98df588b1b8b1dd8bc3de2f33cf` 上的未提交工作树。范围为平台 MCP 页面、原生配置管理组件的嵌入方式、直接相关的页头与导航样式；未审查全仓业务 Harness。按[项目审查原则](../../../../docs/项目审查原则.md)核对实际布局和保存调用链，当前界面约定维护在[平台界面设计](../../../../docs/platform-design/06_界面与前后端渐进建设.md#35-当前第一阶段页面)。

| 发现与影响 | 整改方案及完成结果 | 验证 |
|---|---|---|
| 平台与嵌入组件叠加最大宽度限制，宽屏编辑区仍狭窄 | 去除 MCP 页和内部组件的宽度上限，保留窄列表、扩大编辑区；窄屏上下排列 | 1920、1440、900、390px 的四标签均检查边界和横向溢出 |
| 大块统计占据首屏，固定编排数量不能反映配置事实 | 删除该统计面板，不增加新的计数来源 | 页面直接进入配置与调试内容 |
| 独立工具栏和说明与页头重复 | 只将原生保存按钮移至页头，保留按钮原有 dirty、busy、可写性和校验逻辑 | 无效配置仍阻止保存，检查未写入设置 |
| 切换编排页可能卸载编辑器、丢失草稿 | 隐藏原生管理组件而不卸载；标题使用“编排工具” | 服务、分组、调试和编排往返后草稿仍在 |
| 长 URL、调试输入或结果可能撑破编辑区 | 限制子项最小宽度并允许长内容换行 | 长输入与调试结果在窄屏无横向溢出 |

实施顺序为宽度与统计清理、原生按钮迁移、标签与草稿保留、响应式布局、浏览器对抗检查，均已完成。构建时核对原生组件片段与工具栏替换锚点，锚点变化时构建失败，避免静默丢失保存能力。

[最终浏览器记录](stage1-mcp-layout-final-20261013.json)保存实际全局 DSH 下 16 个布局组合的测量、草稿与校验检查，客户端错误和设置写入均为零；另存[桌面](stage1-mcp-layout-final-desktop-20261013.png)及[手机](stage1-mcp-layout-final-mobile-20261013.png)截图。先前失败记录保留，最终记录独立保存，不覆盖失败观察。

本次证明页面布局、原生校验和交互合同。调试依赖受控外部接口，未据此验收外部业务 MCP、通用手工编排器或业务 Harness 效果。
